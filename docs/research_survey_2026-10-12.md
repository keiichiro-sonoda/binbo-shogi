## 1. 前提(10/12 時点)

- 採用 eval は `task129_student_64m_qsrel_e12`。
  - データ: 64M の全局面。41% を qsearch 末端の局面に置き換え、WS-T + MCTS 8 回で付け直した。
  - 学習: lr 6e-5・Factorizer・12 epoch。
  - 物差し(tanuki- @2 万 / AobaNNUE @1 万)への勝率は 0.65 / 0.61。
- 効いたもの: データ 32M → 64M、学習率 6e-5、Factorizer、置き換え + 付け直し(32M で +64、64M で +28)。
- 効かなかったもの:
  - 学習率の減衰、勝敗の混合、勝率 BCE(−23)
  - 局面の選別・重み付け
  - FV_SCALE を 16 以外にする
  - epoch 24(6e-5 では 12 と同じ)
  - 相関した 2 教師の平均
- 縛り(DESIGN.md):
  - 評価の中身に人間の知識を入れない(棋譜・定跡・手作りの特徴量)。
  - 教師の系統は技巧2 の蒸留と自前の学習。
- 測定はノード固定。大きいネットや遅い特徴量は、ノード固定だと実際より強く出る(§4)。

## 2. 手元で確かめたこと

- **学習データの重複率は 4.2%**(64M 行のうち、異なる局面は 6,124 万)。
  - 10 回以上出る局面は 5.9 万種類で、行数では 3.7%(序盤のランダム手の直後と思われる)。
  - Stockfish の重複除去は ±0(§3.4)。⇒ 重複除去は見送る。
- **やねうら王(手元の 820940e)は HalfKP_vm を既製でサポートしている**。
  - ビルドターゲットは `YANEURAOU_ENGINE_NNUE_HALFKP_VM_256X2_32_32`、特徴量の定義は `eval/nnue/features/half_kp_vm.{h,cpp}`。
  - 入力次元は 5 × 9 × fe_end で、HalfKP の約 56%。
  - エンジン側のコードを書く必要はない。物差しのエンジンは今のままでよい。
- **局面生成の速さ**: 技巧2@d8 の自己対局は、12 worker で 84 分あたり 656 万局面(Task 101)。
  - 熱の規律(並列 4 まで)を守ると、6,400 万局面で約 2 日。
  - CPU の温度は現在、Windows 側のモニタが落ちていて取れない。
- **内部知見との突き合わせ**: Task 103b では、1M 局面で S=8 ≈ S=32 だった(探索の深さより、一手先の戦術の解決が効く)。一方、Task 100〜103 では WS-T の生の value より探索ラベルが +100〜+220 強かった。外部の「探索なしの value の方が教師に良い」(§3.1)とは逆である。当方の WS-T は小さく弱いので、一手先の補正がまだ効く段階と読める。

## 3. 調査結果

### 3.1 教師の質

- **探索スコアを DL の value に付け替えると大きく伸びた**: tanuki- が自前 NNUE の探索スコア 80 億局面を DL水匠で付け直すと、R+104.3±10.1(5,000 局、300s+2s、halfkp_512x2-8-96)[抽出]。
  - https://nodchip.hatenablog.com/entry/2024/12/25/000000
- **深く探索したラベルほど NNUE は弱い**:
  - AobaZero 2026: 「0 visit か 1 visit が一番強く、visit 数が多いほど NNUE は弱くなる」[原文] https://www.apply.computer-shogi.org/wcsc36/appeal/AobaZero/2026csa_appeal2.pdf
  - 山岡氏(dlshogi)も同じ傾向 [原文] https://tadaoyamaoka.hatenablog.com/entry/2025/01/12/111242
  - ⇒ 当方とは逆(§2)。強い value net なら探索は不要、という話と読む。
- **強いエンジンが良い教師とは限らない**(tanuki-、単独教師)[抽出]
  - AobaZero −49.6±9.7
  - Kanade −102.8±15.9
  - あすとら −106〜−112
  - Ryfamate −6.5 [−11.8, −1.2](16,384 局)
- **教師の版を上げても小さい**: AobaZero WCSC34 → 35 で +3.2±2.5(69,370 局)[抽出]。3 教師の均等平均は +4.3(CI は 0 をまたぐ)[抽出]。
- **教師スコアの分布の較正**(tanuki-、2026-09)[抽出]
  - 方法: 教師スコアの順位は保ったまま、参照教師の同じ順位帯の平均値に置き換える(写像表は 12,000 局面から作る)。
  - 結果: 同じ学習順の未較正版との比較(8s+0.08)で、3 系列合算 +44.2 [+35.8, +52.6](6,006 局)。系列別は +52.5 / +45.2 / +37.4。
  - ただし、現行チャンピオン(数百億局面を学習済み)との長時間戦では 59-9-298 で不採用。
  - https://nodchip.hatenablog.com/entry/goal-20260908-071323-e43062ef
- 探索の深さのカリキュラム(やねうら王 2020): depth 8 から順に深くすると良い、とあるが数値はない [抽出]。
- Stockfish 19: 全データを強い Lc0 ネットで付け直した。全体で SF18 比「最大 +44」だが、付け直し単独の寄与は不明 [原文] https://stockfishchess.org/blog/2026/stockfish-19/

### 3.2 自己生成・自己付け直しのループ、局面の分布

- tanuki-: 256x2-32-32 の自己強化(自前の eval で 80 億局面を生成)は R−7.8±9.6。著者は表現力の限界と判断(2022、数十億局面の規模)[抽出]。
- Viridithas(チェス): 今のネットで全データを付け直して +23.9±7.2 〜 +50。ただしエンジン初期の、弱いラベルを直していく段階の数字 [抽出]。
- **自前 NNUE の短い探索の対局局面 + DL 教師**: R+23.0±9.7(tanuki-、nodes=1000、80 億局面)[抽出]。
  - ただし開始局面は floodgate R3900 以上の棋譜から取っている(当方の縛りでは使えない)。
  - https://nodchip.hatenablog.com/entry/2025/10/28/000000
- **方策サンプリングで作った局面は大きく悪化**: 温度 174 で −191.0、下限を設けても −60.1。val loss は改善していた [抽出]。
- 開始局面の手数: 24 手付近がピーク(推測)。0 と 1000 はどちらも悪い [抽出]。
- 別のソースのラベルを混ぜると −10.5±9.6 [抽出]。

### 3.3 データ量

- 将棋 256x2-32-32: 20 億 → 40 億 → 80 億局面で、+2.4 / +4.0(どちらも有意差なし)= 数十億で飽和 [抽出]。
- チェスの単純なネット(Chess768、depth 9 固定)の倍増ごとの伸び [抽出]:

| 区間 | Elo |
|---|---|
| 8M → 16M | +104 |
| 16M → 32M | +55 |
| 32M → 64M | +28 |
| 64M → 128M | +12.6 |

  - https://talkchess.com/viewtopic.php?p=997955
- 当方の 32M → 64M は +100 前後。HalfKP は入力が大きいので、飽和はチェスより遅いと見られる。64M → 128M の将棋の実測は見つからなかった。

### 3.4 学習の手法

- **損失**: Stockfish の現行は、勝率空間の |p−q|^2.5 前後に非対称項を足したもの [原文]。
  - 換算係数は in/out 340/380、offset 270。本番レシピは pow 2.434、asymmetry 0.229。
  - https://github.com/official-stockfish/nnue-pytorch/blob/master/model/config.py
  - 将棋の tanuki- も pow 2.5(〜2.75)の勝率空間 loss が標準 [原文]。
- **勝率のモデルを CE/KL 系にすると −56.5±19.5**(tanuki-)[原文]。当方の BCE −23 と同じ向き。
- **換算係数を動かすと悪化**(tanuki-)[抽出]: score_scaling 511 で −47.9、723 で −66.0、in/out 600/1350 で −20.6。どの回も val loss は下がった。
- 最適化: Stockfish の Ranger → AdamW は ±1 Elo(数十万局)[原文]。将棋では Ranger21 の実装の細部だけで十数〜数十の差 [原文]。SGD+Momentum は −131〜−189 [原文]。
- weight decay: 通常の WD は「Seems worse」(数値なし)[原文]。
- Stockfish のデータローダーの既定 [原文]:
  - 駒取り・王手の除外
  - 評価値と対局結果が食い違う局面の確率的な棄却
  - ランダムに 3/4 を捨てる
  - 序盤 18 手の棄却と、32 手までの確率的な棄却
  - 駒数分布の平坦化

  それぞれの Elo の内訳は非公開。
- 重複除去・追加フィルタ: 成熟したネットで ±0〜+3(Stockfish)[抽出]。

### 3.5 特徴量・構造

- HalfKP_vm: HalfKP 比 +67.5(2021、5,000 局、900s+5s、SGD・Factorizer なし)[抽出] https://nodchip.hatenablog.com/entry/2021/11/14/000000
- HalfKA_hm: HalfKP 比 +21.8±10.1(1024 幅、4,452 局)[原文]。256 幅での比較は見つからなかった。
- 幅: 256x2-8-96 は 512x2-8-96 に −27.2(時間制。256 の方が 25% 速くても負け)[抽出]。
- HalfKP + Mobility は −47(val loss は改善)[抽出]。HalfKPE9 は NPS が約 2/3 [抽出]。
- **tanuki- の構造比較はどれも時間制**。ノード固定だと重い側が甘く出る。

## 4. 提案の詳細

1. **教師スコアの分布の較正**(32M、学習 1 本)
   - 写像の作り方: 学習局面の一部(例: 1 万局面)で、WS-T の付け直しラベルと、同じ局面の技巧2@d8 の評価値(キャッシュの `train_evals`、置き換えた行は符号調整済み)を、それぞれ順位で並べる。WS-T の各順位帯を、技巧2 の同じ順位帯の平均値に置き換える。
   - 順位は変わらないので、局面の良し悪しの判断は WS-T のまま。変わるのは評価値の大きさの付き方だけ。
   - 参照する分布は系譜内の技巧2 なので、縛りには触れない。
   - 対照: `task128_student_qsrelc`(物差しの対局を使い回せる)。
2. **勝率空間の power loss**(32M、学習 1 本)
   - trainer に、損失 = |σ(pred/s) − σ(label/s)|^2.5(s は当方の scale 600 に固定)を追加する。
   - 非対称項は別実験にする。換算係数は動かさない。
   - 対照: 同上。
3. **HalfKP_vm**(32M、学習 1 本)
   - trainer の特徴量の写像、書き出し、0cp ゲート、候補を指すやねうら王のビルド(候補側だけ。物差しのエンジンは不変)を整える。
   - 左右反転の水増しは、vm ではほぼ無意味になるので外す(一変数ではなく「vm 一式」で比べる)。
   - Factorizer の P 表は vm の座標でも同じ形で使える。
4. **データ 128M**
   - 技巧2@d8 の自己対局で +64M を生成する(4 並列で約 2 日。開始局面の作り方は今までどおり)。
   - qsearch で置き換えた後、全行を WS-T で付け直す(約 25h)。64M + 64M で 12 epoch(約 17h)。
   - 変形案: 生成を「自前の eval + やねうら王の 1,000 ノード自己対局」にする(tanuki- で +23 の型。開始局面は当方の方式で)。
5. 要判断 = AobaZero 2025 を第 2 教師にする場合
   - 最小実験は次の 3 段。
     1. 特徴量の実装を検証する(初期局面の値・符号、WS-T との相関)。
     2. 32M で「WS-T 単独 / 平均 / Aoba 単独」を学習する。
     3. 判定は **tanuki- 側だけ**で行う(AobaNNUE 側は偏るため)。
   - 採るなら、物差しの AobaNNUE を別系統に替えることも検討が要る。

## 5. 勧めないもの

- **ネットの拡大・LayerStack・SFNN**: 時間制でも NPS の低下で負ける例が多い(−28〜−40)。ノード固定の当方では、甘く出て判断を誤る。
- **HalfKPE9・Mobility 特徴量**: NPS が下がる(−47、NPS 2/3)。
- **方策サンプリングで作る局面**: −60〜−191。
- **WS-T の探索なしラベル**: 当方では探索ラベルが +100〜+220 強かった(Task 100〜103)。
- **勝率への換算係数の大きな変更、CE/KL 系の勝率モデル**: −20〜−66 / −57。
- **SGD、optimizer の総入れ替え**: 前者は大負け。後者は ±1 で、手間に見合わない。
- **重複除去**: 重複は 4.2% で、Stockfish でも ±0。
- **自前 eval による自己強化ループ(付け直しだけ)**: 当方の WS-T より自前 NNUE の方が教師として良いという根拠がない。tanuki- の 256 幅では −7.8。
