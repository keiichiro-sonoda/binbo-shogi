# 公開前の検査

このリポジトリは公開されている。**push は point of no return**: 参照を消しても SHA を知っていれば
取れることがあり, fork・キャッシュ・公開イベントの収集にも渡る。鍵は失効させるしかなく,
機械や人の同定情報には取り消す手段が無い。だから push の前に, 取り消せないものだけを機械で止める。

## 仕掛け方 (クローンごとに 1 回)

```sh
git config core.hooksPath .githooks                       # pre-push フックを有効にする
git config publish.privateRepo <非公開のリポジトリのパス>   # 無い機械では none
# 非公開の語の一覧を <git の共通ディレクトリ>/info/publish-denylist に置く (1 行 1 語)
```

- フックは `.git/hooks` に置かない。`core.hooksPath` なら追跡しているファイルを直接実行するので,
  フックを直したときに古い写しが残る事故が起きない (Git Bash の `ln -s` は設定によって黙ってコピーになる)。
- **非公開の語の一覧はこのリポジトリに入れない。** 公開物に書けば, 一覧そのものが漏洩になる。
  `git rev-parse --git-common-dir` の下の `info/` は push されない。
- どちらも用意していなければ, 門番は「指摘なし」ではなく**終了コード 2 (検査できない)** で止まる。

## 何を見るか

`tools/publish_lint.py` が, push で新しく公開されるコミットを **1 つずつ** 見る
(足して次のコミットで消しても, 履歴には残るため)。フックは push する ref を 1 つずつ渡す
(HEAD ではない。別のブランチにいるまま `git push origin <ブランチ>` しても検査される)。

| ID | 止めるもの |
|---|---|
| P1 | 鍵・トークンらしき文字列 |
| P2 | ユーザー名入りのパス, メールアドレス (`Co-Authored-By:` などの trailer 行を除く), IP アドレス |
| P3 | 非公開の語 (一覧にあるもの。語そのものは出力しない) |
| P4 | 非公開の履歴のコミットへの参照 (`publish.privateRepo` で解決できる 16 進の並び) |
| P5 | 会話ログの URL, `Claude-Session:` の行, エージェントの一時領域や記憶へのリンク |
| P6 | 公開しないと決めたパス (大会の本番用の道具, 手順書, アピール文書など), 重み・データ・鍵・ログの実体 |
| P7 | バイナリ (中身を検査できないので, 合格に混ぜない) |

手で回すとき:

```sh
uv run --no-project python -I tools/publish_lint.py --remote origin   # origin に無いコミットを見る
uv run --no-project --with pytest python -m pytest tests/test_publish_lint.py   # 門番自身の試験
```

鳴ったら直してから push する。**`--no-verify` で抜けない。** 誤報なら門番の方を直す
(誤報を放っておくと, 鳴っても止めない癖がつき, 本物の漏洩を通す)。

## 門番がわざと見ないもの

説明の誤り, 数字の取り残し, 命名, 設計。どれも後から直せる。直せるものを門番に積むと,
鳴っても止めない癖がつく。

## 機械では見られないもの (push の前に目で読む)

- **貼り付けた出力。** 実データで動かした出力を, そのまま例示や報告に貼ると, パスの形をしていない
  情報 (リポジトリ名, 仮想環境の場所, サービス名) まで運ぶ。一覧に無い名前は機械が見落とす。
  例示は最初から架空のデータで作る。
- **画像・図の写り込み** (P7 で止まるので, 出す前に開いて見る)。
- **内輪の呼び名と, 1 台の話の一般化。** 端末の愛称のような呼び名は外の人に通じない。
  消すときも「作業していた 1 台の性質」を「環境全体の性質」として書き直さない。
- **PR・Issue・コメントの本文。** git の外なので, この門番も `.gitignore` も見ていない。
  PR は作ったら削除できない (クローズしても差分は認証なしで取れる)。本文は出す前に読み返す。
- **辿れないものへの参照。** 非公開の履歴, 公開していないファイル, 会話の中の指示は, 読む人が開けない。
  必要な中身は本文に書く。

## この仕組み自体を疑う

門番は, 失敗が成功と見分けのつかない形で壊れる (検査が走っていないのに「指摘なし」と出る,
常に止まるのに「効いている」と読む)。門番を直したら, **止まるべき時に止まり, 通るべき時に通る**
ことを両方確かめる。`tests/test_publish_lint.py` は両方を並べてある。
