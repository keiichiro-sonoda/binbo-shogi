## 0. 結論

binbo(物量より工夫)に合い、根拠が強い順に並べる。

| 順 | 案 | 根拠の強さ | コスト | 期待 | 主なリスク |
|---|---|---|---|---|---|
| 1 | **FV_SCALE の掃引**(探索に渡す評価値の倍率) | 強い(将棋で 45〜75 Elo の振れ) | 対局のみ(1 点 ≈35 分)、学習なし | 0〜+70 | 物差しへの選び過ぎ → 新しい seed で確認 |
| 2 | **qsearch 置換**(取り合い局面を、静止局面に「置き換える」。ラベルは元のまま) | 強い(公式手順、tanuki- で無しは −116) | CPU 1 パス + 特徴キャッシュ作り直し + 学習。再ラベル不要 | 捨てていた 37% の局面が戻る(データ増)+ 静止化 | 既存の除外と効果が重なる / 置換表の扱い |
| 3 | **学習率の引き上げ**(1e-5 → 3e-5) | 中(手元の証拠: 学習不足の兆候) | 学習 1 本 | ±、当たれば同じ計算量で強くなる | 過学習(lr 1e-3 は失敗済み) |
| 4 | **Factorizer**(玉位置に依存しない補助の重みを学習中だけ足し、書き出し時に合算) | 割れている(SF 小〜中データで有効 / tanuki- 80 億局面で −44) | trainer 改修(推論・形式は不変) | 小データほど有利な理屈 | 実装の手間、効かない可能性 |
| 要判断 | **系統の違う第 2 の教師**(例: AobaZero の生 value)とのアンサンブル | 強い(業界の最大レバー) | GPU 約 0.5〜1 日(推定) | 大 | 教師方針(DESIGN.md)・物差し AobaNNUE との相関・入力履歴・ライセンス |

勧めないもの: 幅の拡大、誤評価局面の採掘、詰みラベル、重み平均(SWA/EMA)、さらなる除外フィルタ。理由は §5。

## 2. 手元で確かめたこと(一次)

- **qsearch_psv の実装**(`engines/yaneuraou/source/engine/yaneuraou-engine/yaneuraou-search.cpp`、commit 820940e)[原文]
  - 各レコードで `qsearch<PV>` を回し、PV を実際に指し進めた leaf で局面を置き換える。
  - **score(ラベル)は付け直さない**。PV が奇数手なら score と game_result の符号を反転する。
  - move は none になり、gamePly は leaf の手数になる。
  - qsearch に使う評価関数は、エンジンにロードした eval。
  - root は「TT hit なし扱い」で始まるが、内部ノードでは置換表を引く(2603 行の `tt.probe`)。
    - tanuki- は「シャッフル時の qsearch で置換表を有効化すると −108.9±10.1」と報告している[抽出]。
    - ⇒ Hash を最小にし、workers の数を変えても出力が同一か(決定性)を確かめる必要がある。
- **FV_SCALE**: やねうら王の USI オプション(既定 16、範囲 1〜128。ソースのコメントに「水匠5では24がベストらしい」)。
  - 当方の書き出しは、FV16 で当方の cp(600 × logit)になるよう出力層に倍率を畳み込んでいる(`docs/nnue_yaneura_export.md`)。
  - FV を 24 にすると、探索が見る評価値は 2/3 倍になる。
  - 対局ツールの `--a-opt FV_SCALE=N` で、学習なしに変えられる。
- **学習不足の兆候**(Task 109 の重み)
  - 第 1 層(int16、×127)の |w| は 99.9% 点が 9、最大 59。Task 106(12 epoch)では 99.9% 点が 5、最大 22 で、epoch を増やすと伸びている。
  - int8 層の飽和はゼロで、水匠11 のような上限張り付きは無い。
  - best epoch は 22/24。train loss は 14k、val loss は 48k で差が大きい。
  - Task 061(小データ時代)の学習率比較: 3e-5 が +240.8、1e-4 が +208、1e-5 が +188.5(採用は 1e-5)。
- **詰み局面はほぼ無い**: Task 106 で残る局面から 24,000 を抜き出したところ、手番側に 5 手詰があるものは 0 件。詰みラベルの修正は効く余地が小さい。
- **学習時間**: 32M・12 epoch ≈1.9 時間、64M・24 epoch ≈8 時間(RTX 4060 Ti)。

## 3. 調査結果(テーマ別)

### 3.1 FV_SCALE / 評価値の尺度
- tanuki-(nodchip)の掃引
  - 2022-07-02、256x2-32-32、水匠5 教師、各 2,000 局、±15 [抽出]: 16 が +10.3、20 が +18.6、24 が −2.6、28 が −22.8、32 が −25.2。
  - 2025-01-31、DL水匠 value で付け直し、λ=1、各 5,000 局 [一次]: **16 が −41.4、28 が +33.9(差 ≈75)**。
    - 著者は、教師の評価値が大きく、探索部の想定を超えて枝刈りが狂うと解釈している。
    - 水匠作者の助言: λ=1(教師ラベルのみ)なら FV を大きくする。
  - 2025-03-04、AobaZero で付け直し [一次]: 16 が −110.2、39 が −43.9。
  - 2025-05-08、score_scaling 723 [抽出]: 20 が −66.8、48 が +5.6。
  - **最適値は学習設定ごとに動く**。評価値の分布の比から機械的に決めた 14 は、24 比 −115 [−144, −87](620 局、2026-09-08)[一次]。⇒ **対局で掃引するしかない**。
- 水匠5: FV を 16 から上げながら再学習して +R100(局数なし)[抽出]。
- やねうら王作者: 旧評価関数には FV 20〜36 を推奨(2025-02-26)[一次]。
- AobaNNUE: 勝率→評価値の係数を 756 → 600 にして「+40 ほど」、FV 既定は 40 [原文]。
- 水匠11: 教師の 3 割以上が極端な勝率。出力が大きすぎて FV80 が最良 [原文]。
- 強い圧縮(600/1350)は −20.6±9.6 [抽出]。
- **当方への含意**: 当方は「DL 型の教師 value をそのまま正解にしている(λ=1)」。nodchip で FV16 が大きく外れたのと同じ型なので、16 が最適である保証は無い。学習なしで試せる。

### 3.2 qsearch 置換(局面を静止局面に置き換える)
- 公式手順(wiki「評価関数の学習」)は「DL で付け直し → qsearch_psv → split/shuffle → 学習」[原文]。先にラベルを付け、それを leaf に引き継ぐ。
- tanuki-、蒸留、512x2-8-96、80 億局面 [抽出]
  - qsearch 無しは、同じ流れで qsearch ありと比べて **−116.2±16.1**(2,000 局、2025-06-14)。なお tanuki- の学習器には捕獲・王手スキップが無い。
  - あり/なしを混ぜると −53.4。
- AobaNNUE: 「静止探索で動く局面は書き換え」たうえで、leaf を AobaZero の 0 手読みで付け直している [原文]。作者の 256x2-32-32 では +148〜+207 [一次、計測条件は要確認]。
- Stockfish は「除外」(smart fen skipping)を使う。SEE≥0 の取りだけを除く絞り込みで +2 傾向 [一次]。
- **当方への含意**
  - Task 106 の除外は「捨てる」側。Task 114〜116 で「難しい局面を捨てると損」と分かった。
  - 置き換えなら、捨てていた 37% の行(32M で 1,183 万行)が静止局面として戻る。
  - 32M → 64M で +100 前後出た(Task 107)ので、行の回復だけでも効く見込みがある。
  - 再ラベルは不要(ラベルは元局面の探索ラベルのまま)。

### 3.3 学習の設定
- Stockfish の Sopel 実験ログ [一次]
  - 損失: 勝率空間の |p−q|^k で、k=2.6 は MSE 比 +10(20k nodes)。CE は MSE と同等以下。
  - 大きな誤差の勾配を切ると約 −58。
- LR: 指数減衰と段階減衰は同等。周期的 LR は悪化。Ranger21 は収束が速いだけ。
- SWA/EMA: 定量的な証拠が無い。SF は 2026-07 にレシピから削除した [一次]。
- 同じデータでの再学習は利得なし。より良いデータ(Lc0)での再学習は +20 [一次]。
- やねうら王 BulletOu の既定 [原文]
  - Ranger、lr 8.75e-4 → 1e-5、1 億局面ごとに ×0.992、batch 65536、λ=1。
  - 損失は勝率空間の二乗誤差(WRM)、FV24 を想定。
- tanuki-: SGD lr 0.5 + Newbob。Ranger に替えると −40.3 [抽出]。
- **当方への含意**
  - 当方の Adam lr 1e-5 は他の学習器と比べて小さい。§2 の学習不足の兆候とも合う。
  - 勝率空間の power loss は候補だが、当方の勝率 BCE は −23 だったので中リスク。

### 3.4 Factorizer(仮想特徴)
- Stockfish: 最初から外すと **約 −24**(16B 局面)。効くのは学習の初期で、75 epoch 時点では外しても同等 [一次]。データ量との関係を直接測った結果は無い。
- tanuki-: HalfKP^(K+P)、256x2-32-32、80 億局面で **−44.4±9.7**(2022-06-20)[抽出]。1024 幅で −133 はバグ疑い。
- BulletOu: FT factorizer は既定で ON。Elo は未公表 [原文]。
- **当方への含意**
  - 当方の学習量(数千万局面 × 24 epoch)は SF の「初期」の範囲。
  - HalfKP は玉 81 マスに分かれるので重みが疎で、train と val の差も大きい。理屈では小データ向き。
  - ただし大データでの実測は負。試すなら 32M のふるい分け 1 本。

### 3.5 アーキテクチャ
- tanuki-(512x2-8-96 比、80 億局面)[抽出]: 1024 幅が +10.1(NPS は 2/3)、1536 幅が −24.5、256x2-8-96 が −27〜−32。1024x2-8-32 は 256x2-32-32 比 −74.4 で過学習(2022-06-27)。
- 奏乗(水匠10 比、各 1,000 局)[原文]: 512 幅が −173.7、1024 と 1536 が −167.5。「512x2_8_64 以上に拡張しても性能向上はほとんどない」。
- Stockfish: 256x2-32-32 → 512x2-16-32 で +51(20k nodes、16B 局面)、15〜20% 遅い。データ量では 1 億局面が 40 億局面比 −251 で、小データは過学習 [一次]。
- **当方への含意**: 数千万局面では広げても過学習側。固定ノードの測定では甘く出る。いまはやらない。

### 3.6 データ
- データ量が最大の効き目

- 早い手数のスキップ: SF で +2.9 だが、開始局面の集合で符号が変わる(DFRC −9.0)[一次]。

### 3.9 測定上の注意
- 固定ノードでは、大きいネットが甘く出る。SF の 1536 幅は 25k nodes で +26.9 だったが、STC では −6.1 [一次]。
- SF は、固定ノードを候補の選別だけに使い、採否は実時間で決める。
- 当方の 1〜4 位は推論速度を変えないので、ノード固定の物差しのままで公平に比べられる。

## 4. 提案(実施順)

1. **FV_SCALE 掃引**(Task 118 候補)
   - 採用 eval(Task 109)のまま、FV を例えば 12 / 20 / 24 / 32 にして標準の物差しで測る。FV16 は Task 113 の対局を再利用する。
   - 最良の値を、新しい seed で確認してから採用する(選び過ぎの補正)。
   - 以後の学生の比較は、決めた FV で行う(対照の対局は、その FV で指し直す)。
   - 所要: 1 点 ≈35 分 × 4 + 確認 ≈1 時間。CPU 4 並列、学習なし。
2. **qsearch 置換**(Task 119 候補)
   - hcpe → psv → `qsearch_psv`(採用 eval、Hash 最小、決定性チェック)→ hcp に戻す → 32M 特徴キャッシュを作り直す。ラベルは元のまま(奇数手は符号反転)。
   - 腕: 対照 = Task 106(除外)、候補 A = 全行を置換(除外なし、行は約 1.6 倍)、候補 B = 除外後の行だけ置換(静止化の効果だけを見る)。
   - 32M・12 epoch でふるい分け、勝った方を 64M で確認する。
3. **学習率 3e-5**: 32M・12 epoch、対照 = Task 106。勝てば 64M・24 epoch の作り直しの時間を短くできる。
4. **Factorizer**: trainer に P 仮想特徴を追加し、書き出し時に HalfKP へ合算する。合算後の重みで QAT とクリップを行い、0cp ゲートを維持する。32M でふるい分け。
5. 必要に応じて: 勝率空間の power loss、重複率の測定(多ければ除去)、ラベル尺度の調整(FV の結果を見てから)。

## 5. 勧めないもの

- **幅の拡大・LayerStack**: 数千万局面では過学習側。奏乗は 512 以上で頭打ち。固定ノードで甘く出る。
- **誤評価局面の採掘**: 単独では負け(dlshogi)。分布がずれると大きく負ける(tanuki- −191)。
- **詰みラベル**: 証拠が無く、当方の局面に詰みがほぼ無い。
- **SWA/EMA**: 定量的な証拠が無い(SF は削除済み)。
- **さらなる除外フィルタ**: Task 114〜116 と SF の SEE 実験(+2)から、余地が小さい。
- **SPSA による探索パラメータ調整**: やねうら王は「+R50 ぐらい」と言うが、数万局が要り、評価の A/B と交絡する。FV 掃引がその 1 次元版にあたる。
