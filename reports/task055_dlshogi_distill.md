# Task 055: 教師を dlshogi に差し替えて再蒸留 — 結果ログ

目的: 「先生の質が Lv3+ の評価天井の真因か」を純粋に切り分ける。**教師ラベルだけ**を技巧2 depth8 cp → dlshogi
(model-dr2_exhi の静的 value→cp)に差し替え、生徒アーキ(HalfKP shared fd8)・データ局面(同 8M)・探索・学習目標
(cp+clamp5000+mse+mirror)は全固定。同一探索部で評価だけ差し替えて技巧2 Lv1-Lv4 と棋力比較。

## 実装・検証(整列が正しさの要)

- **8M 全 re-score(整列付き)**: `trainer/dlshogi_rescore.py --cache-dir` で採用 8M キャッシュの局面を prepare_data と
  同一順序で dlshogi 評価 → `train/val_dlshogi_evals.npy`。**整列 assert: re-score の gikou-eval == cache の `*_evals.npy`
  完全一致**(train 7.95M / val 50K)= 局面とラベルがズレていないことを証明。22分(6070 pos/sec, VRAM 2.8GB)。
  dlshogi cp std 2396(技巧 1963=鋭い)、技巧 cp との相関 0.921。
- **教師差し替え学習**: `train_nnue --eval-npy`(ラベルだけ dlshogi、他は採用と同一)。`t055_dlshogi_cp_8m`。
  Rust parity 2.90e-06、詰み発見 OK(ラベルの向きも正しい)。

## 棋力(8M, 同一seed=Task052, 3seed×12=36局/Lv, 同一探索部・eval だけ差し替え)

| Level | dlshogi 教師版 | 技巧2 教師版(採用基準) | Δ |
|---|---|---|---|
| Lv1 | 54.2% | **69.4%** | −15.2pp |
| Lv2 | 22.2% | **44.4%** | −22.2pp |
| Lv3 | 12.5% | **20.8%** | −8.3pp |

**より強い先生(dlshogi)で蒸留した生徒は、全レベルで明確に弱くなった**(全 4 レベルで一貫=雑音でない)。
ラベルは正しい(整列 assert・符号一致 0.845=逆でない・parity・詰み・coherent な指し手)。**仮説と逆の重要な負の結果**。

## なぜ「より強い先生」で弱くなったか(解釈)

1. **生徒は dlshogi のラベルを技巧2 のラベルより当てはめられない**: val_corr が dlshogi 教師版 **0.85** vs 技巧2 教師版 **0.90**。
   = 小さい KP 生徒は dlshogi(深い CNN)の評価関数を**表現しきれない**。技巧2 は KPP 評価で**生徒の KP 表現に近い**ため、
   生徒は技巧2 の判断をよく真似できる。**蒸留の質は「生徒が先生の関数を表現できるか」に依存**する。
2. **ラベルの種類が違う(静的 vs 探索済み)**: 技巧2 ラベルは **depth8 で探索した値**(戦術・先読みが焼き込まれている)、
   dlshogi ラベルは **NN の静的 value(1-ply)**。静的 eval の生徒には、探索が焼き込まれた技巧2 ラベルの方が良い目標。
   (※ dlshogi の NN value は数百万自己対戦の知識を持ち「真の値」推定としては強いが、生徒が表現できないと活きない。)

→ **「先生がエンジンとして強い」≠「良い蒸留先」**。先生の評価関数を生徒が表現できるか(teacher-student マッチ)と、
   ラベルが探索済みか、が効く。dlshogi は強いが、KP 生徒には**遠すぎる先生**だった。

## 決着と次段

- **dlshogi 静的 value の蒸留は棋力を下げる → 不採用**。採用 EvalFile は **技巧2 蒸留 HalfKP shared 8M のまま**。
- **「先生の質が律速」仮説は素朴な value 差し替えでは確認されず**(むしろ悪化)。これで Lv3/Lv4 の壁は
  **探索でも(049-050)・KP系表現でも(052-053)・素朴な先生差し替えでも(055)破れない**。
- **積み上がった示唆 = 真の壁は小さい KP 生徒(fd8)の表現容量**: 技巧2 教師でも val_corr ~0.90(decisive の約10%で符号誤り)が
  天井で、容量増(fd↑ 042)も richer 表現(052/053)も強い先生(055)も、この生徒には届かない/活かせない。
- **次段候補(BACKLOG)**:
  1. **searched dlshogi(MCTS value)を教師に**: ラベルに探索を焼き込めば上の (2) は解消。だが (1) の表現ギャップは残る見込み
     (dlshogi engine の MCTS が要る=別セットアップ・遅い)。(2) と (1) の切り分けになる。
  2. **生徒の根本強化**: 表現ギャップ (1) が本丸なら、KP fd8 でなく**より大きい/別パラダイムの生徒**(HalfKA を活かす/
     深い NN/量子化で深さ確保)が要る。052(HalfKA Lv3 +18pp)は生徒側の表現が効いた唯一の例=生徒の器が鍵かもしれない。
