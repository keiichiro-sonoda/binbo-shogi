# Task 040: 教師データ 生400万(計800万 with mirror)— 伸び継続(逓減は緩やか)+ 棋力が動いた

## 結論

- データ量の軸をさらに押した: 生200万 → **生400万(計800万 with mirror)**。構成は fd8+mirror+cp回帰(clamp±5000, MSE)・教師 depth=8 据え置き、量だけ増。
- **伸びは継続、逓減は緩やか**(主指標 val decisive 予測、同一 held-out で直接比較):
  - 生100万 **2185(正解の56%)** → 生200万 **2455(63%)** → 生400万 **2652(68%)**(正解 3915)。
  - 倍化あたりの伸び: 100→200万 **+270**、200→400万 **+197**(約73%に逓減=緩やか。**まだ頭打ちでない**)。
  - **gap 809→541→285**(良い縮み方: val が上がって縮む)。val_corr **0.80→0.84→0.87**、decisive 符号一致 0.83→0.85→0.875。
- **棋力が初めて動いた**: 技巧2 Lv1(1秒8局)**0-8 → 0-7-1(初の引分, score 6.2%)、avg_plies 77→105(粘り激増)**。
  `nnue-diag` 対局符号一致 **26/27(96%)**、対局は詰まされず最大手数へ。度合いの改善が実戦の粘りに転化し始めた。
- **データ量はまだ効く軸**。次段も増量(生800万〜)を継続する価値あり。GPU で再学習は軽い(4M を ~8s/ep, mem 74MB)、収集は 14700KF 並列(2M/23分)。
- 採用モデル更新 = **`model_cp_fd8_mirror_4m`**(生400万+mirror, GPU 学習)。

## 1. 新規教師データ生成(生+200万, 14700KF 並列)

- `gen-teacher ... run2m_c 2000000 --depth 8 --seed 20280101`(run1m/run1m_b と別 seed=多様性、depth 同一=質は不変, 量だけ)。
- 結果: **2,000,000 局面 / 200 shard / 失敗0 / 23.21分**(5.85× 並列)。crash 168 全復旧(restarts 168, timeouts 0)。eval ±30500。
- 検証: cshogi 読み戻し ok(is_ok)、shard/manifest 健全。非コミット `~/binbo-shogi-data/teacher/run2m_c`(約400MB)。

## 2. 生400万 + mirror で学習(GPU)

- cache_4m = run1m + run1m_b + run2m_c の**全局面**= **train 395万**、**val = run1m の held-out 5万(Tasks 036〜039 と同一=系列比較可)**。ペア漏れなし。
- 構成据え置き fd8+mirror+cp(clamp5000,MSE)、GPU 20 epochs(best @ep4)。
- **GPU 実測**: ~8s/epoch(3.95M, batch1024)、**GPU メモリ 74.3MB**(fd8 は極小=16GB の 0.5%、バッチ調整不要)。CPU比 ~4.5倍速。
  - epoch1 の train/val loss 差が **+3127**(生100万は +309k, 生200万 +128k)= データ量で過学習が劇的に減少。

## 3. 効果(系列比較 = データ量の限界の見極め)

`pred_dispersion`(decisive |target|≥1500, val=run1m val。正解 val |cp| mean=3915):

| 生データ | 実効(mirror) | **val 度合い** | %正解 | gap | val_corr | decisive_sign | 倍化Δval |
|---|---|---:|---:|---:|---:|---:|---:|
| 100万 | 200万 | 2185 | 56% | 809 | 0.80 | 0.83 | — |
| 200万 | 400万 | 2455 | 63% | 541 | 0.84 | 0.85 | +270 |
| **400万** | **800万** | **2652** | **68%** | **285** | **0.87** | **0.875** | **+197** |

- **val が単調上昇(2185→2455→2652)し gap が単調縮小(809→541→285)**。train はほぼ不変〜微減(2994/2996/2937)=情報追加の良い縮み方(正則化の「両方下がる」と質が逆)を継続。
- **伸びは逓減するが緩やか**(+270→+197, ~73%)。**まだ頭打ちではない**(4M でも +197=+8% の実質的な伸び)。データ量は引き続き productive。
- 代表局面静的分解能は curated ノイズで 37×(marginal=34 と小さく出たため;頑健指標は上の val 系列)。

## 4. 棋力(初の前進)

- `nnue-vs-gikou` Lv1(1秒, 8局, 先後入替): **0-7-1(初の引分, score_rate 6.2%)**。**avg_plies 77→105 と粘りが激増**、depth 5.36。
- `nnue-diag` 対局: 符号一致 **26/27(96%)**、outcome=max_plies(詰まされず60手到達)。度合いの改善が実戦の粘りに転化し始めた最初の兆候。
- スケール/数値一致: GPU 学習重み export → Rust と Python eval 一致(`verify_nnue_rust` **3.63e-06** < 1e-3, ok)。fd8 は Rust 無改修。
- 回帰: perft 1〜5 完全一致、`selfplay` 完走、対 Random **20勝0敗**、`cargo test` 16/16(本タスクはコード変更なし)。

## 所見と次段

- **データ量はまだ効く**(val 56→63→68%、棋力 0-8→0-7-1、avg_plies 77→105)。逓減は緩やかで頭打ちではない。
  → **次段も増量を継続**(生800万〜=計1600万 with mirror)。GPU 学習は軽い(4M ~8s/ep, 74MB)、収集は 14700KF 並列(2M/23分)で現実的。

- 主指標は引き続き `pred_dispersion` の val 度合い(良い縮み方)+ Lv1 の粘り/勝ち星。度合いが正解(3915)へ近づくほど勝ち星が見えてくる兆し。
