# Task 176: 判定を安くする (2026-10-23)

**推奨は「800局ごとの保守的な早期合格 + 見込み薄の打ち切り」。** 現行に近い検出率で、差0の候補は約30%、+10 / +20 / +30 Eloは約12 / 9 / 26%の主判定局数を節約する見込み。過去26比較の再生では約45%減、現行で通った6候補をすべて残した。将来も完全に同じ判断をする保証ではない。既存コード・ログ・方針は変更していない。コミットなし。

## 実測: 大部分は探索の応答待ち

`std_frame.py`、`t106_filter.run_chunks`、`t103_absolute.paired_series_delta`、Rustハーネスと既存TSVを確認。s280–282で完全な48チャンクが揃うのは**27ネット、129,600局**。約40ネットという見積もりを、そのまま独立標本数には使わない。旧確認組も含む有効TSVは1,760本。初回走査で不完全な12本を除外し、SHA256付きmanifestで入力を固定した。うち8本は強い比較用ネットが99局などで終わったもの、4本は走査時点で進行中の対局だった。ヘッダの「recorded only」に反してRustの対局ループはSPRT境界で終了するため、`elapsed_ms=`だけで100局完了とは扱えない。

| 1局の加重平均 | tanuki @20k | Aoba @10k |
|---|---:|---:|
| 手数 (序盤6手込み) | 119.2 | 123.7 |
| 対局時間 | 4,629ms | 4,584ms |
| 候補の応答待ち合計 | 3,827ms | 3,978ms |
| 物差しの応答待ち合計 | 801ms | 604ms |
| その他の対局処理 | 1.49ms | 1.48ms |

待ち時間にはプロセスのスケジューリング、USI通信も入る。純粋な探索CPU時間とは分離できない。上限100kより実ノードが少ないのは詰み等の早い終局もあるためで、これだけでは無駄とは言えない。

- **毎局再起動していない**。2本を起動・`isready`した後、100局を再利用し、毎局は`usinewgame`を送る。起動・重み読み込み・hash確保はTSVの総計時より前なので、直接の内訳はない。連続実行だったTask154_R / 166_R1 / R2では、mtimeと総計時から推定した波間の空白は1.2–2.0秒、5区間計7.5–8.2秒。起動等を合わせても主因ではないという傍証。初回起動は測れない。
- **8枠の終了待ちがある**。48チャンクの記録済み所要時間を固定して再配置すると、空き枠は中央値4.5%、待たず次を投入するキュー化の短縮は中央値**3.3%** (範囲0.8–7.8%)。実機での速度保証ではない。計算上のframe所要時間は43–60分、中央値45分。遅い時間帯・再開・同時負荷は区別が必要。下記の各800局の完了を待つ案には、この3.3%を重ねて足さない。
- **2本とも同時に探索するわけではない**。交互に`go`するため8対局の主な探索並列度は約8。CPUは14700KFの20物理コア/28論理スレッドで、28本を埋めてはいない。一方16エンジンの常駐メモリが必要。既定hash 1GiB、約1.2GB/本という既存記録から12対局では約29GBに達し、実際にswapした経緯がある。Task166_R1の8枠稼働中508観測でもRAM平均23.4GB、CPU平均38.2%、温度95百分位85°C。同時負荷を含むため並列度別ベンチにはならない。**8を維持**し、将来の8/10比較はRAM・温度を測って別途行う。常駐swap量だけでは現在のページ入出力は分からない。
- hash縮小、`isready`/TT初期化の変更、100局の内部順序変更、チャンクをまたぐエンジン再利用は探索状態を変え得る。今回の節約に算入しない。100局チャンクを丸ごと並べ替えるのは既存キャッシュと両立する。

## 統計: 素朴な途中観察は使わない

当時の基準 (Task129/142/154) との26比較を作り、差の絶対値40 Elo以下の20比較を分散の供給元にした。各供給元の**同じ序盤・先後2局・物差し2本・候補と基準**を保持する。候補/基準を交換した観測も加えて差0の母集団を作り、確率を指数傾斜して、プールしたロジット差が**厳密に0 / +10 / +20 / +30 Elo**になるよう較正した。旧ネットの観測差を「真の効果」とは扱わない。

各効果30,000反復、seed=176202610。下表は**平均候補局数 /「強い」と判定する率**。0の率が偽陽性率、正効果の見送り率は100%からその率を引いたもの。現行の95%両側区間は「強い」側には約2.5%を使う。途中の打ち切りは「弱い」の証明にはしない。

| 規則 | 真の差0 | +10 | +20 | +30 |
|---|---:|---:|---:|---:|
| 現行4,800局固定 | 4800 / 2.45% | 4800 / 27.08% | 4800 / 77.20% | 4800 / 98.18% |
| 毎回Z=1.96で判定 (不可) | 4380 / 7.97% | 3905 / 38.90% | 2733 / 83.38% | 1741 / 98.83% |
| O'Brien–Fleming型のみ | 4762 / 2.48% | 4577 / 26.32% | 3850 / 75.86% | 2933 / 97.92% |
| 同上 + 見込み薄の打ち切り | 3226 / 2.46% | 3979 / 26.16% | 3758 / 75.69% | 2927 / 97.84% |
| **保守案 (下記)** | **3354 / 2.48%** | **4240 / 26.99%** | **4390 / 77.16%** | **3542 / 98.10%** |
| SPRT 0対+20、4,800局上限 | 3119 / 0.83% | 4063 / 12.80% | 3850 / 56.53% | 2864 / 92.74% |

保守案の見送り率は+10 / +20 / +30で73.01 / 22.84 / 1.90%、現行は72.92 / 22.80 / 1.82%。**現行自体も+10を約73%見送る**。SPRTはα=.025、β=.10、正規近似の対数尤度境界+3.584 / −2.277。上限で境界未到達なら保留とし、後付けの固定検定はしない。+20で約39%が保留になるため、この上限のまま置換する案は勧めない。TSVの既存W/D/L SPRTは候補対物差しの絶対成績を見ており、候補−採用の検定には流用できない。

**精度・限界**: Monte Carloの95%誤差は偽陽性率で約±0.18ポイント、最大約±0.57ポイント。最終検定は既存percentile bootstrapのデルタ法近似であり、全反復に20万回bootstrapを重ねてはいない。実データの点推定は既存19比較のJSONと1e−10以内で一致し、26比較では同じ25セル分布のpercentile bootstrapも再計算した。中心化したElo影響量の再標本化、50序盤チャンク単位の再標本化でも、保守案の平均局数は約3,367 / 4,240 / 4,383 / 3,541局、検出率の差は小さい。母集団の定常性、未経験のネット、固定序盤への選択適応まで保証しない。SPRTも既知分散の厳密検定ではない。

## 事前登録できる保守案

1. ノード・エンジン・hash・序盤6手・上限320手・100局チャンクを維持。`for chunk=0..7 → set=s280,s281,s282 → anchor=tanuki,Aoba`の順に並べ、**800 / 1600 / 2400 / 3200 / 4000 / 4800局**でだけ判断する。1回に既存8チャンク、両物差しが同じ序盤で揃ってから見る。集合ごとのチャンク数の差は最大1。順序も事前に固定し、結果を見て並べ替えない。交互化はアンカー/集合の片寄りを防ぐ目的で、過去データの最初800局の誤差を必ず小さくするわけではなかった。
2. `n=候補局数/4`、`μ=E(P候補)−E(P基準)`、`E(p)=400 log10(p/(1−p))`。序盤iの候補・基準それぞれ4局平均を`c_i,b_i`とし、`ψ_i=E'(P候補)(c_i−P候補)−E'(P基準)(b_i−P基準)`。`s=SD(ψ_i)`、`SE=s/√n`、`Z=μ/SE`。**先後と物差し2本を同じ序盤クラスタにする**。
3. 最初の5回は**Z≥3.50**、最終回は**Z≥1.97**なら新しい組の確認へ。独立な30万本の正規過程で較正した最終境界1.966を保守側へ丸めた値。通常の途中CIを有意判定に使わず、停止時の通常95%CIにも95%被覆を主張しない。
4. 合格しなかった途中回は、残りが真に+10 Eloだった場合の最終合格確率の近似
   `CP=Φ((nμ + 10(1200−n) − 1.97s√1200) / (s√(1200−n)))`
   が**1%以下ならNO_BETTERで終了**。これは計画上の打ち切りで、母効果が負という宣言ではない。最終回不合格は保留/不採用。延長しない。
5. 読み取り異常、非合法手、未完了チャンク、seed・先後・序盤の不一致はINVALID。基準の欠けた局を無視して判定しない。候補・基準・順序・境界・確認seedを結果を見る前に登録する。

この順序で26比較を再生すると平均2,646局、固定の6合格をすべて保持、追加合格なし。記録済み時間を固定した再生は平均48.4分→26.6分 (**45%減**) だった。これは提案を作ったデータ上の記述で、独立した性能保証ではない。より積極的なO'Brien–Fleming型は`Z≥2.06/√(n/1200)`で、節約は大きいが+20の検出率が約1.5ポイント落ちるため第二候補とする。[境界の考え方](https://search.r-project.org/CRAN/refmans/ldbounds/html/commonbounds.html)、[SPRTの前提と境界](https://ucb-stat-159-s21.github.io/site/Notes/sprt.html)。

## 少ない局数で同じ精度になるか / 残すもの

- 現在の基準の得点率はtanuki .7473、Aoba .6875。二値・独立近似なら、50%付近の物差しはEloの1局あたり情報量が高く、同精度に必要な局数は現状比約**.76 / .86** (約24 / 14%減)。ただし強い物差しの探索費用、引き分け、候補と基準の共分散も変わる。**既存ログだけでは同精度・短時間を実証できない**。較正用の新しい比較と基準frame取り直しが必要で、今回の節約に足さない。
- 現行はすでに先後ペアをbootstrapするので、pentanomialへの名称変更だけでは精度は増えない。実測の先後ペア化による差の分散比は中央値.991、範囲.935–1.043。候補・基準の対応付けの分散比も独立扱いに対し中央値.968程度。両物差しを同一序盤に束ねた分散/現行分散は.946–1.067。大きな「半分の局数」の根拠はない。候補−基準には単独の5分類でなく、ペア得点の**5×5結合**、さらに両物差しの共分散が必要。
- **fresh-set確認は残す**。新しい重ならないseedで候補・基準を各800局×2本、差の点推定>0。**micro確認も残す**。同じ新しい組で双方各800局、差の点推定>0。既存conf154は通常+19.5 / micro+14.0、conf168は+75.9 / +45.1と再集計できたが、2例で確認の誤判定率は推定できない。確認にも途中観察を追加しない。採用は作者判断。
- 表の節約は**主判定のみ**。確認は合計4,800局 (基準側も新規)。確認へ進む確率をqとすると期待費用は`E[主判定局数]+4800q`、さらに採用候補を次の再利用基準にするときは、**標準4,800局の未実施分を埋める**。採用までの総費用が一律45%減るとは言えない。
