## 判定 = **`REPLICATED`**(終端)

> **独立に seed を振った2本の学習走が、いずれも自身の初期値 WS-T を外部(技巧2@6)で超えた。** run2 単独 **+26.19 [+1.86, +50.42]**、run1 単独 +28.65 [+3.79, +53.51]、pooled **+27.42 [+10.05, +44.79]**(2,504 clean ペア)。走間差は −2.45 [−37.4, +32.4] で区別不能。

### この判定が licence する範囲(事前登録どおり)
- **licence する**: 「r=0.50 混合ループの正転写は**単一学習軌跡の産物ではない**」。096 の留保④は**定性的に解消**。
- **licence しない**: 「r=0.50 レシピの期待効果の95%区間が [+10.05, +44.79]」。pooled 区間は**実現した2ネットに条件付き**の固定効果量であり、学習シード間分散 τ² は入っていない(k=2 は 1df ゆえ推定不能。DerSimonian–Laird は半幅 `12.71×|Δ₁−Δ₂|/2` となり無意味なので**計算していない**)。∴ **留保④の定量部分(レシピ一般の効果量に区間を与える)は未解消**で、k≥5 が必要。
- 効果量として引くべき数字は **run2 単独の +26.19**(唯一の選択汚染なし推定)。096 が有意だったから本タスクが存在する以上、run1 と pooled は上方偏りを持つ。**実際 pooled +27.42 は run2 単独 +26.19 よりわずかに高く、この偏りの向きと整合する**。

## 過程で判明した計測系の欠陥(2件。いずれも判定に影響なし)

### 1. シード変更ガードの閾値が尺度を誤っていた(初回起動が21分で停止)
初回は `SEED_DID_NOT_CHANGE` で停止。帰属を実測で切り分けた結果 **シードは正しく適用されており、閾値が誤り**だった。anchor index stream は `SeedSequence([anchor_seed, iteration])` の決定論的関数なので直接比較でき、**iteration 1/2/3/25 すべてで同位置一致 0/32768、集合の重なりは独立抽選の期待値どおり**(579/474/560/523 vs 期待537)。ckpt の config も `seed=anchor_seed=20269700` を保持。

誤りの内容: `anchor_ce` は 256×128=**32,768標本の平均**なので、同一2Mプールからの独立2抽選でも差の SD は約 **0.012**。実測 |Δ| = 0.0045 は「変わった場合」に普通に出る値であり、閾値 **0.005**(`REGRESSION_TOL` = 同一設定下のコード回帰検出用)を別文脈へ流用したのが誤りで、構成上かなりの偽陽性率を持っていた。

**修正は閾値の緩和ではなく、ノイズのある代理統計を機構そのものの決定論的検査へ置換**(`assert_anchor_stream_changed`、preflight で GPU コストゼロ)。置換後は偽陽性が原理的に起きず、「モデル軌跡の差が anchor 系統の差に見える」偽陰性も起きない。**双方向で検証**(正しいシードで通過/同一シードで送出)。スモークの2 iter は正しいシードで生成済みゆえ有効で、再開時に流用された。

### 2. `SESSION_RATE_SKEW_UNEXPLAINED` は帳簿式が狭すぎた偽陽性
唯一立ったフラグ。だが分解すると**実質的な証拠はすべて「強さで説明される」方向**:
- 遅い系列(r050s2 **7.10局/分**)= **強い系列**(score **.1629** vs WS-T 9.31局/分・.1434)✓
- **ABBA 符号一致**(r050s2 は先攻ブロックでも後攻ブロックでも遅い)✓
- 落ちたのは `wins==count(resign)` / `losses==count(mate)` の帳簿式のみ

原因: **`rep_win`/`rep_lose`(千日手系、256局中≤2局)は AZ視点の score には反映されるが reason 名は審判視点**で、私の恒等式が取りこぼしていた。繰り込めば厳密に一致する(例 block12 r050s2: `mate 216 + rep_win 1 = 217 = L`、`resign 30 = W`)。∴ **フラグは偽陽性**で、096 の同定(resign=gikou投了=AZ勝ち → 勝ちが多い → 対局が長い → 局/分低下)は成立している。コードは**事後に直していない**(結果を見てから通るまで直すのを避けるため)。修正は次タスクへ申し送り。

### ★プロセス上の所見(再発防止として記録)
**今セッションで同種のミスが4件**発生した — 095 の回帰ゲート閾値、096 の層別推定量(two-stage の二重計上)、097 のシードガード閾値、097 の帳簿式。**共通の失敗様式は「別文脈の許容値・推定量・恒等式を、その文脈でのノイズ尺度や網羅性を確かめずに転用した」こと**。4件とも科学的判定は歪めていない(095/096 は主判定が pooled ベースで健全、097 の2件は起動可否と記述フラグのみ)が、096 では「最大の弱点」という誤った記述を公表し Erratum を要した。

**今後の作法として固定する**: 閾値・恒等式・推定量を新設するときは、**必ず帰無対照でノイズ床/網羅性を実測してから定数を決め、その対照を self-test に同梱する**。097 で導入した `null_control_selftest`(two-stage の1.20×膨張を毎回再現)と `assert_anchor_stream_changed`(機構の直接検査)はこの作法の実例。

## 申し送り — (a) 運搬路タスク【本命】

正転写がレシピ水準で再現したので、次の問いは**「この利得を champion(NNUE)へ運べるか」**。ループ内のネットが外部で強いことと、そこから製品が強くなることは別問題で、そこが製品価値の分かれ目。

- **一変数 = value 凍結の緩和**(r=0.50 / 25iter / sims32 は固定)。WS-T value への蒸留正則化(λ 対数ラダー)で出力を拘束しつつ共有幹を更新し、**凍結(096/097)vs 緩和**を一変数比較。凍結は「価値を守るが新情報を入れない」設計なので、value に新情報を入れる唯一の経路。
- **判定は二層**: ①外部 = 本タスクと同一ハーネス(gikou@6, sims128, ABBA)で ΔElo vs WS-T。②**教師性 = 084方式の value 相対判定**(候補 value で 2M rescore → `train_nnue --qat --qat-tie` → `eval_vs_eval.sh` 0cp ゲートの yane-vs-yane SPRT)。092-0 で退役した補助 head 橋は使わない。
- **★085 の反転を必ず適用**: 2M での勝ちは **32M 確認の資格まで**(2M→32M で符号が反転した実績があるため、2M PASS を最終改善と呼ばない)。
- **★n=1 の定量部分は依然未解消**: レシピ一般の効果量に区間が要るなら k≥5(+3.9h/走)。運搬路タスクの判定に必要かは、そこで測る量が「この2ネット」で足りるかによる。少なくとも運搬路の**存在**を測るだけなら不要。
- **コスト設計**: λ ラダー3点 ×(学習3.9h + 外部1,224ペア10h)は過大 ⇒ **まず λ 1点 + 外部 400ペア(≈3.5h)でスクリーニング**し、通ったものだけ本測定へ。
- **計測系の宿題(小)**: `SESSION_RATE_SKEW` の帳簿式を `wins == resign + (AZ勝ちに繰り込む千日手系)` へ一般化、15%閾値も勝率調整済み指標へ。
