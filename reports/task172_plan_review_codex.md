**ラベルと勝敗：実物で見つかった修正点**

`work/task129/labels/train_dlshogi_evals.npy` と B 各 `cache/train_evals.npy` は int16。独立に各131,072行を抽出した結果は次の通り。平均・SD は ±2000 制限後、率は生ラベル。

**現在の A は「勝敗あり0.6%」と一致しない。** 等間隔標本でも非ゼロ約78%。由来の再監査なしに使わない。`--cp-result-lambda 0.7` は A にも作用する。`--wdl-known-only` は cp objective では追加の制御にならない。cp 実装自体が引き分け／不明（0）を混合から外す。

A は `value_to_cp()` の `1200*atanh(v)`（生成時 ±5000）。B は表示 cp を `sign(cp)*ceil(abs(cp)*90/100)` で戻した内部 Value（詰み ±32000）。NNUE の `forward*600` は配備後の内部 Value に対応する。**そのまま回帰できるが、勝率の較正まで同じではない。B をさらに0.9倍／100÷90倍する根拠はない。** 分布差には局面差も混ざる。過去の同一 A 局面でも、WS-T／task142 d9 の制限後平均は −186.36／+45.78、ブロック相関 .888〜.890（Task147点検）。

各65,536特徴行の標本間に A–B、B1–B2 の完全一致はなかった。同局面較正はできず、全件非重複も保証しない。**初回は尺度補正なし。B の勝敗混合だけを明示する。** B の非ゼロ行だけ `600*logit(0.7*sigmoid(raw/600)+0.3*result)`（result=勝1/負0）、最後に ±2000 制限。raw を先に制限しない。A と B の引き分けは純評価値を使う。入力側で A の WDL を0にするか、B だけ混合済みラベルを作り CLI の lambda を1にする。既存 A は上書きしない。B の混合後clamp率は20.30%／17.00%。
