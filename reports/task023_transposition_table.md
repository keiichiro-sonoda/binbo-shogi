# Task 023: 置換表(TT, HashMap, 標準版)

## 結論

- αβ探索に **置換表(TT)** を入れた(`src/search.rs`)。キーは Zobrist `pos.key()`、HashMap で
  score/bound/depth/best_move を保存。**depth ≥ 要求 depth のとき、より深い結果も流用する標準版**。
- **速くなった**: 深いほど効く。深さ5で **ノード約33-34%・時間約30-34%削減**(深さ3以下はほぼ0)。
  - 中盤・深さ5: 150.2M → 98.4M ノード(34.5%減)、235.7s → 159.0s(32.5%減)。
- **弱くなっていない**(完全一致の代わりの担保):
  - ベンチ全局面・全深さで **TT あり/なしの探索スコアが完全一致**(値を壊していない)。
  - 同深さ自己対戦で TT あり が TT なしに**負け越さない**(深さ3: 19-19、深さ4: 1-1)。
  - 終盤で**詰みを正しく発見**(score=29997=MATE-3。詰み値 ply 補正が機能)。
- スコープ厳守: 固定サイズ配列・反復深化・ムーブオーダリング・MTD(f)/PVS・静止探索・時間管理は
  未実装(best_move は保存するが順序付けには未使用)。

## 設計(`src/search.rs`)

- **キー**: `pos.key()`(yasai の Zobrist u64)。HashMap は完全な u64 をキーにするので添字衝突なし
  (真の Zobrist 衝突のみ、無視できる)。深さはキーに含めない(局面のみ)。
- **エントリ**: `{ score: i32, bound: {Exact, Lower, Upper}, depth: u16, best_move }`。
- **フラグ判定**(探索後): `best <= alpha_orig` → Upper、`best >= beta` → Lower、それ以外 → Exact。
- **probe**(`entry.depth >= depth` のとき): Exact → 値を返す / Lower かつ `score>=beta` → cut /
  Upper かつ `score<=alpha` → cut。depth 不足なら枝刈りに使わない。
- **上書き方針**: **深さ優先**(既存より深い結果は残す、同深さは新しい結果で上書き)。記録: 素朴な
  「常に上書き」ではなく depth-preferred を採用(浅い境界で深い Exact を潰さないため)。
- **クリア**: `search_root` の冒頭で毎回クリア(= think ごとにクリア。持ち越しは反復深化導入時に検討)。
- **詰み値 ply 補正(GHI 対策, 必須)**:
  - 評価帯 `±28000` < 詰み閾値 `29000` < `VALUE_MATE=30000` < `VALUE_INF`。
  - 格納時 `score_to_tt`: 詰み値なら `±ply` してノード相対へ。取出時 `score_from_tt`: `∓ply` で
    現在 ply の root 相対へ復元。単体テスト `mate_score_tt_round_trip` で往復一致を固定。
- best_move は保存のみ(将来のムーブオーダリング用、今は順序に未使用)。

## 「弱くなっていない」確認(完全一致の代わり)

- **スコア一致**: 上表のとおり TT あり/なしで探索スコアが全一致 → TT が値を壊していない。
- **同深さ自己対戦**(`nnue-ttmatch`, 乱数オープニング, 色入替):
  - 深さ3: TT 19 / 非TT 19 / 引分 2 → **互角(19-19)**。深さ3は TT が枝刈りを起こさない領域
    (ベンチで0%削減)なので両者は同一の指し手=対称的に互角。**負け越しゼロ**。
  - 深さ4: TT 1 / 非TT 1 / 引分 2(4局のみ。深さ4は1局約28秒で多数は非現実的)→ **1-1、負け越しなし**。
    深さ4は TT が枝刈りを起こす領域だが、より深い結果の流用は探索を**より正確**にするだけなので
    弱くならない(理論的にも崩れない)。
- **詰み**: ベンチ終盤で TT ありでも score=MATE-3 を正しく出す(ply 補正が効いている)。
- **回帰**: TT エンジン(深さ3)対 Random = 30戦30勝。
