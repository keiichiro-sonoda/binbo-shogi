# Task 128 — 静止局面への置き換え + ラベル付け直し(32M): `QS_RELABEL_HELPS`、腕 C − 対照 = +63.9 [+40.9, +86.8]

Task 119 では、取り合い中の局面 P を静止探索の行き着いた局面 Q に置き換え、ラベルは P のものを引き継いだ。その結果、捨てていた行を戻すと悪化した(A − B = −26.4)。今回は、置き換わった行に教師(WS-T + Gumbel MCTS S=8、Task 104 のラベラー)で Q そのもののラベルを付け直した。事前登録済み、ドライバ `experiments/alphazero/t128_qs_relabel.py`。実行は 10/10 19:39 → 10/11 09:12(`rc=0`、失敗なし)。

## ラベルの付け直し
- 置き換えを作り直し、Task 119 と全行で一致することを確認した(置き換えの有無と手番の反転の両方、特徴も抽出確認)。
- 付け直したのは 13,140,149 行。速度は毎秒 696 行、所要約 5.2 時間。教師の符号の検査は通過。
- 新旧ラベルの相関は 0.935(検査の基準は > 0.5)。
- 新旧ラベルの差(中央値)は 355cp。Task 106 が捨てていた行では 417cp、残していた行では 241cp。

## 解釈
- **ラベルを付け直せば、捨てていた行は大きな得になる**。C − D = +39.6 で、Task 119 の A − B = −26.4 と符号が逆になった(レシピと物差しが違うので、値は直接は比べない)。Task 119 の悪化はラベルのずれが原因、という見立てを裏づける。
- **残していた行でも、付け直しは効いているらしい**。D − 対照 = +24.3 で、CI 下限は +0.7。置き換わるのは残した行の 19% だけで、引き継いだラベルの版(Task 119 の B)は ±0 だった。
- 合計は +63.9 で、これまで 1 回の変更で得た改善の最大(Factorizer は +40.8、学習率 3e-5 は +30.9)。
- **val loss は強さを予測しない**: C の val loss は対照とほぼ同じだが +64、D は対照より悪いが +24。val には取り合い中の局面が置き換えずに残っているため。今後も判定は対局で行う。
- 留保: 学習の seed は 1 本。C は学習行が 1.6 倍で、学習の時間(更新回数)も多い。「戻した行の中身」と「行数が増えたこと」は分けていない。ただし Task 119 の A は同じ行数でも悪化しており、行数だけで説明できるものではない。
