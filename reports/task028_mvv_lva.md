## 知識ゼロ縛りとの線引き(DESIGN.md に記録)

- MVV-LVA の駒価値序列(歩 < 香・桂 < 銀・金 < 角 < 飛、成駒は元駒+α)は**順序のヒント専用**。
  評価関数(NNUE)とは別物・別の場所(`order_value`)に置き、NNUE には一切関与させない。
- ムーブオーダリングは αβ の最終的な最善手・評価値を変えない(Task 025 で実証)。よって人間の駒得感覚は
  評価には入らず、探索速度にのみ影響する。
- 知識ゼロ縛りは「評価の中身」への縛りであり、探索順序の実装ヒントはその対象外、と明文化(`DESIGN.md`)。

## A. MVV-LVA の実装(`src/search.rs`)

- **順序専用の駒価値表 `order_value`**(評価とは無関係のざっくり値)。玉は最大値(合法手では取れない)。
- **`order_key(pos, mv, hash_move)`**: ハッシュムーブ=最優先、取る手=`1000 + 被取得駒価値×32 − 攻撃駒価値`
  (MVV 主・LVA 従)、静かな手=0。駒打ちは「取る手ではない」ので静かな手側。**NNUE は呼ばない**(価値表を引くだけ)。
  - 取る手の判定: 盤上手(打ちでない)かつ移動先に駒がある。被取得=移動先の駒、攻撃=動かす駒。
- **`order_moves`**: `use_mvv_lva` なら `order_key` 降順に `sort_unstable`、そうでなければハッシュムーブを
  先頭へ(Task 025)。優先順位 = **1. ハッシュムーブ → 2. MVV-LVA の取る手 → 3. 静かな手**。
  ハッシュムーブが取る手と重複しても最優先キーで先頭に来るので二重化しない。
- `Opts.use_mvv_lva` フラグで on/off 切替(効果を分離測定)。

## B. 思考ログ(info)保存

- **USI option `LogFile`**(string, 既定空)にパスを設定すると、各 go の思考をそのファイルに追記:

  ```
  # === usinewgame ===
  # move 1 side b sfen lnsgkgsnl/1r5b1/.../LNSGKGSNL b -
  info depth 1 score cp 182 nodes 31 time 0
  ...
  info depth 5 score cp 136 nodes 143072 time 152
  bestmove 5g5f
  # move 2 side w sfen ...
  ...
  ```
- 各手について **到達深さ・評価値(cp/mate)・ノード数・時間** と最終手が残り、対局後に振り返れる。
- **stdout の USI 通信は不変**(ログは別経路=ファイル)。info の live 表示(Task 027)もそのまま。
- ShogiHome 側でも USI 通信ログを保存できる(stdout の info を捕捉)が、`LogFile` は**エンジン自前**で
  確実に残す手段。作者は ShogiHome の登録エンジンに USI option `LogFile` で絶対パスを指定すればよい。
