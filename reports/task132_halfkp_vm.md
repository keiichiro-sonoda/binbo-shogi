# Task 132 — HalfKP_vm(重みの共有として実装、32M): `VM_HURTS`、vm − 対照 = −33.7 [−56.4, −11.0]

調査(`docs/research_survey_2026-10-12.md` の提案 3)に基づき、HalfKP_vm を試した。HalfKP_vm は、玉が 6〜9 筋にいる視点を左右反転する特徴量。事前登録済み、ドライバ `experiments/alphazero/t132_halfkp_vm.py`。実行は 10/13 09:25 → 14:01(`rc=0`、失敗なし)。

## 実装
- HalfKP_vm は、HalfKP で W[玉, 駒] = W[反転した玉, 反転した駒] と重みを共有するのと同じ計算になる。
- そこで、学習側の重みの束ねとして実装した: `trainer/kp.vm_mirror_map` を作り、Task 059 の tie の対応表に合成する(`--vm`)。
- 書き出しは普通の HalfKP(反転側の行には同じ値)。そのため、やねうら王のビルド、Rust 側の評価、0cp ゲートは変えていない。
- 独立した重みの行は 124,254 から 69,030 に減った(やねうら王の HalfKP_vm の次元は 69,660)。
- `--vm` を付けなければ、従来の動作は変わらない。

## 検査
- 0cp ゲートは GREEN。
- 両方の玉が 5 筋にない 2,054 局面とその左右反転で、評価値が完全に一致した(2,054/2,054)。vm なしの対照では 33/2,054 だった。

## 学習(Task 128 腕 C と同じ条件 + `--vm`)

CI 上限 < 0 なので **`VM_HURTS`**。不採用。

## 解釈
- **val loss は下がったのに弱くなった**。Task 117・128・130・131 と同じく、val loss と強さが逆に動いた例。
- 有力な原因は、**2 つの視点の座標がばらばらに反転すること**。HalfKP_vm では、自玉側の半分は自玉の位置で、相手玉側の半分は相手玉の位置で、それぞれ独立に反転するかが決まる。両玉が盤の別々の側にいると、2 つの半分で座標の向きが食い違う。後段の層は「どちらの筋で何が起きているか」を一貫して読めなくなる。
- 重みを共有して得られるはずだった学習効率は、当方ではすでに左右反転の水増しと Factorizer で取れていたらしい(調査時の見立てどおり)。残ったのは、上の座標の食い違いの損だけ、と読める。
- tanuki- の +67.5(2021)は、水増しも Factorizer もない古い学習器での比較だった。
- 留保: 学習 seed は 1 本。
