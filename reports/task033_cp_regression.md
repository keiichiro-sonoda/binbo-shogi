# Task 033: 評価関数の再学習 — cp 直接回帰で「度合いの圧縮」を解く

## 結論

- 学習の**目標設計だけ**を変えて再学習した(データ・NNUE 構造は流用)。勝率 sigmoid をやめ、技巧2の評価値 cp を
  **直接回帰**(±C クランプ + Huber/MSE)。スケールは `forward()*600 = cp`(Rust の `EVAL_SCALE` と同一)なので
  **Rust 推論は無改修**(`src/eval/nnue.rs` / `src/search.rs` 不変)。
- 採用モデル **`model_cp_mse_c5000`**(MSE, clamp ±5000)。
- **度合いの圧縮は明確に緩和:**
  - 代表局面の **decisive 評価値が約3倍**(飛車得 静的 446→**1097**、飛車損 −117→**−280**、中盤 1612→**1889**)。
  - **静的分解能 1.86× → 3.95×(2.1倍)**(技巧2 22.6×)。
  - 検証相関(cp 回帰)**0.62→0.75**、decisive 局面の符号一致(val)**0.80**。
- **実戦の符号一致(向きの判断)が劇的に改善:** Task 031 の負け筋で生徒は形勢の向きを取り違えていた(70%, 19/27)が、
  本モデルは診断した全手で技巧2 d8 と**符号一致 100%(21/21)**。「負けているのに気づかない」欠陥が大きく改善。
- **棋力(技巧2 Lv1, 1秒/手, 8局): 0-8 のまま(勝ち星は出ず)。** ただし形勢の向きは正しく読めるようになった。
  decisive の度合いは技巧2の依然 ~0.4倍(飛車得 1097 vs 2635)で、残る差は**目標設計ではなくデータ/容量**を示唆
  (次段)。task の主目標(度合いが出る・勝ち負けへの勾配が立つ)は達成、勝率移動はボーナスで未達。
- スケール一致を数値検証: Rust forward == Python forward(最大誤差 **2.2e-06** < 1e-3, `nnue_rust_matches_python=ok`)。
  cp 回帰で forward は decisive 局面で **±9(= ±5400cp)**まで伸びる(勝率 sigmoid では飽和して伸びなかった)。

## 目標設計の変更(`trainer/train_nnue.py`)

- `--objective cp`(既定)を追加。ターゲット = `clamp(eval_cp, ±C)`。損失 = `--loss huber|mse`(`--huber-delta`)。
  `pred_cp = forward * scale_cp(600)` を cp 空間で回帰する。`winrate`(Task 017 の sigmoid+BCE)は `--objective winrate` で残置。
- 指標を追加: val の **decisive 符号一致**(|cp|≥500 で向き一致率)と **|pred| の decisive/near 別平均**(度合いが分離したか)。
  Task 017 の教訓(val ロスは度合いの圧縮を見逃す)に対応し、選定は val ロス単独でなく分解能/符号で行う。
- データは既存流用(Task 016 の100万局面、Task 017 の .npy キャッシュ `/tmp/binbo-task017/cache`)。NNUE 構造は不変。

### なぜ MSE + 広いクランプか(クランプと損失の役割)

- **クランプ C**: 正解の極端値(詰み絡み ±30000)を抑える。ただし飛車得は技巧2で ~2600cp なので、C=2000 だと decisive 正解が
  2000 で頭打ちになり度合いが出ない → **C を 3000/5000 に広げると decisive 正解が活き、度合いが伸びた**。
- **損失**: Huber δ=600 は大きな残差で勾配を δ=600 に頭打ちさせる → decisive 正解(2000〜5000)への引きが弱く度合いが伸びない。
  クランプ済みで外れ値が無いので **MSE が安全に使え、度合いを強く押せる**(二乗罰が under-prediction を強く罰する)。

## スケール一致(学習=推論)

- 設計: モデル出力 `forward` を学習で `forward*600 ≈ clamp(cp)` に合わせ、Rust は従来どおり `eval_to_int(forward)=round(forward*600)`。
  **Rust 側 `EVAL_SCALE=600` と一致 → 推論コード無改修**。
- 検証(`verify_nnue_rust.py`, C5000, 5000局面): 最大絶対誤差 **2.159e-06** < 1e-3, `nnue_rust_matches_python=ok`。
  forward は decisive で ±8〜9(= ±4800〜5400cp)まで出る(勝率目標では飽和して出なかった大きさ)。
