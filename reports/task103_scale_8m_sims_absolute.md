## 判定の含意
- **利得の正体は「深い探索」ではなく「一手先の混合」**: S=8(max_visits 1.25)で S=32 と同等以上の利得が出た(103b)。099 で S=32→128→512 と深くしても探索値が gold へ近づかなかったことと整合する。探索ラベル = 「方策 prior で重み付けした一手先の値の平均」であり、静的評価では表現できない一手の戦術(取られる駒・王手回避)を静的評価の目標に焼き込んでいる、と読める。
- **利得はデータ量で縮むが消えない形**(103a): 8M で +107、減少幅は 42→31→17 と鈍化し、漸近モデルの漸近値 ≈ +70。085 型(2M +237 → 32M −36)の完全反転とは異なる曲線。ただし直接対局の差は相性成分を含み(103c: champion フレーム +88、技巧2@6 フレーム +42)、一般棋力換算は漸近でも +30〜+60 と見るべき。
- **102b と合わせた機構像**: eval スケールでは説明できず(102b)、深さにも鈍感(103b)、データで完全には消えない(103a)⇒ **「一手先解決という新情報」が主、小データ正則化が従**。
- **プロジェクト地図への含意**: 技巧2@d8 に無い情報を単機で作る候補として、AZ ループでなく **AZ 網の一手先探索ラベル**が最も安価に実在を示した。32M(champion 構成)で本当に +30 以上残るかが「champion 超え」への次の関門。S=8 なら 32M rescore ≈ 9.3h、学生学習 ≈ 3h、SPRT ≈ 数時間 = **1 日で回せる**。
- 留保: (1) 各点とも学生 1 本(学習 seed n=1)。(2) 4M 以上で 098 レシピは過学習側(best epoch 5–7)。(3) 相性成分は 4M でしか測っていない。(4) S=8 と S=32 は 1M の 1 点比較。

## 申し送り
- **本命 = 32M 決戦(S=8)**: `caches/shared_32m` を S=8 で rescore(≈9.3h、part は run1m/run1m_b/run2m_c/run4m_d の S=8 分は無いので全量新規。S=32 の part は流用不可)→ champion 構成(`task064_32m_lr1e-5` と同レシピ)で学生学習 → champion と SPRT(`scripts/eval_vs_eval.sh`)。085 と同じ土俵。S=8 vs S=32 の差が 32M でも無いと仮定するのは 1 点根拠なので、余力があれば 8M で S=8 の点も取る(≈2.3h)。
- **16M 点(S=32)**: 曲線の漸近値確認用。新規 8M 行 ≈ 12h GPU。32M 決戦が優先なら省略可。
- **相性成分の切り分け**: 8M 探索学生・生学生を champion/技巧2@6 に当てる(103c の 8M 版、CPU 2.5h)。
- **レシピ**: 4M 以上では epoch/lr の見直し(best epoch 5–7)。ただし規模曲線の比較可能性を保つため、曲線用は 098 レシピ固定のまま。
- 計測系: t100 の ETA 表示が再利用行を含む(表示のみ)/ `--raw-student` の 0cp ログ流用先に `_0cp_raw.log` も追加 / `SEARCH_ASYMMETRY` は nodes 比を主に。いずれも次タスクの実装時に反映。
