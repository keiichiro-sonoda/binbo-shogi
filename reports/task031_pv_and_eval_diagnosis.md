# Task 031: pv(読み筋)出力 + 評価の質の診断(生徒 NNUE vs 技巧2)

## 結論

- **A. pv(読み筋)出力**を実装。反復深化の各深さ完了時に `info ... pv <手列>` を出し、思考ログ(LogFile)にも
  残す。詰み発見時は pv が詰み手順になり `score mate N` と長さが一致。探索の最善手・スコア・ノード数は不変
  (pv は探索結果に影響しない副次構造)=無回帰。
- **B. 評価の質の診断**(診断専用 CLI `nnue-diag`)。代表局面と「生徒(先手) vs 技巧2 depth1」の実戦を、
  生徒 NNUE 評価(静的 + 探索)と技巧2 depth1/depth8 評価で1手ずつ突き合わせた。
- **診断の核心: 生徒の評価は「符号(どちらが有利か)はほぼ正しいが、有利/不利の度合いを判別できない(0付近に圧縮)」。**
  - 代表局面で**符号は6/6一致**。明確な駒得局面でも向きは当てる。
  - しかし**大小が激しく圧縮**: 飛車得を生徒は **+603**(技巧2 **+2635**)、飛車損を生徒は **−129**(技巧2 **−2405**)
    としか見ない。0から離れるほど圧縮率が悪化(near-equal は ~等倍、決定的局面で 1/5〜1/20)。
  - 実戦では、形勢が傾く中盤で生徒が「微有利」と誤認(生徒 **+35〜+42** に対し技巧2 **−354〜−805**)。
    自分が数百cp 負けていることに気づかないため、守りに回らず取り返しのつかない差にされる。
  - これが「**depth5〜6 まで読む生徒が depth1 の技巧2に負ける**」(Task 030)の機序: 葉の評価がどこも「ほぼ互角」に
    見えるため、深く読んでも勝ち/負けへ向かう勾配が立たない。
- **次段への示唆: 主戦場は静止探索ではなく「評価の再学習・キャリブレーション」。**
  圧縮は局所的な戦術崩れではなく評価全体の鈍さなので、静止探索では本質的に直らない。
  正則化の見直し(wd=1e-3 は出力を縮める方向 → wd=1e-4 既存重みと比較)、目標スケール(勝率 sigmoid は決定局面で
  飽和し勾配が消える → cp 直接回帰や温度の見直し)、決定的局面のデータ比率が候補。

## A. pv(読み筋)出力

### 実装(`src/search.rs`)
- **三角 PV テーブル**(`Searcher.pv: Vec<Vec<Move>>`、`pv[ply]` = その ply 以下の最善手順)。各ノードで α を更新する
  指し手が出たら `pv[ply] = mv ++ pv[ply+1]` と組み立て(`update_pv`)、探索が実際に選んだ手順をそのまま保持する。
- **TT exact ヒットでの PV 補完**(`fill_pv_from_tt`): 置換表の exact カットで部分木を飛ばすと PV がそこで切れるため、
  そのノードから TT の best_move を辿って PV を再構成(合法性チェック + 同一局面/長さ上限でループ防止)。反復深化で
  PV 上のノードが TT exact で当たるのは普通に起きるので、これがないと数手で切れる。
- ノード先頭で `pv[ply]` をクリア(葉・終端・fail-low が親に古い手順を残さない)。**探索のノード数・最善手・スコアは不変**
  (pv は読み取り専用の副次構造で、カット条件や着手生成を変えない)。
- `SearchResult.pv` / `IterInfo.pv` で結果を返す。`MAX_PV_LEN=64`(安全上限)。

### 実装(`src/main.rs`)
- 反復深化の各深さ完了コールバックで `info depth .. score .. nodes .. time .. pv <USI手列>` を出力(`format_pv`)。
  `emit_info` 時は stdout に flush、`LogFile` 指定時は同じ行をログにも残す。
- `ThinkResult.pv`/`ponder` に最善手順を載せる(stdout の `bestmove` 出力契約は不変)。

### 確認(USI セッション)
- 通常局面(`startpos moves 7g7f 3c3d`、Depth 8):
  ```
  info depth 8 score cp 105 nodes 10603938 time 12303 pv 8h2b+ 3a2b 5i6h 5a4b 6h7h B*3c 6g6f 3c6f
  ```
  合法な8手の読み筋。深さが進むと pv も伸びる。
- 詰み局面(`4k4/9/4g4/9/9/9/4R4/9/4K4 b - 1`):
  ```
  info depth 3 score mate 3 nodes 736 time 0 pv 5g5c+ 5a4a G*2b
  bestmove 5g5c+
  ```
  **`score mate 3` と pv の手数(3)が一致**、末尾 `G*2b` が詰ます手。pv は実際に指せる合法手順。

## B. 評価の質の診断(`nnue-diag`)

診断 CLI を追加:
```
nnue-diag <weights_bin> <gikou_path> [seed] [student_ms] [gikou_depth] [opening_plies] [max_plies]
```
- 生徒: 静的評価 `eval_to_int(logit*600)`(手番側 cp 相当)と、時間制限つき探索(pv 付き)。
- 技巧2: `eval_sfen`(`src/teacher/gikou.rs` に追加、cp/mate を生で返す。`analyze_sfen` を再構成して流用)で
  `go depth 1`(≒Lv1 の着手)と `go depth 8`(強い物差し)の score/bestmove を取得。
- 符号・傾向を比較(スケールは生徒 logit×600 と技巧2 cp で異なるので、向きと大小傾向を見る)。

実走条件: 重み `model_wd1e-3/nnue_f32.bin`、技巧2 v2.0.2、student_ms=2000、gikou_depth=8、出だし6手、最大60手、seed 20260623。

|---|---:|---:|---|---:|---:|:--:|---:|

| 終盤(物差し) | 113 | **mate3** | 5g5c+ | mate3 | mate3 | ✓ | 詰み一致 |

- **符号は6/6一致**。明確に駒得/駒損の局面でも有利の向きは外さない(致命的な符号反転バグはない)。
- **大小は0から離れるほど圧縮**。near-equal(序盤)は技巧2と同程度、戦術中盤で 0.67、駒得で 0.23、駒損で 0.05。
  飛車を1枚得しても生徒には「+0.6 程度の小有利」、1枚損しても「ほぼ互角(−0.13)」にしか見えない。

- 終盤の物差し局面では `mate3` を技巧2と一致して発見(評価ではなく探索が詰みを掴む)。pv も `5g5c+ 5a4a G*2b`。

集計: 診断した生徒の手 **27手**、技巧2 d8 と**符号一致 19/27**、生徒最善 = 技巧2 d8 最善 **8/27**。結果は max_plies 引分(60手で打ち切り)。

読み取れること:
- **0付近の符号ノイズ**(ply8/16): わずかな有利不利の向きを取り違える。near-equal では評価の分解能が足りない。
- **形勢が傾く瞬間の致命的な誤認**(ply22〜26): 生徒の**静的評価は +178〜+253(明確に有利と誤読)**、探索でも +35〜+42。
  実際は技巧2 d8 で −354〜−805 = すでに数百cp 負け。**自分が負けていることに気づかないため反撃・受けに転じない**。
- **圧縮は終盤まで継続**: 符号が合っても度合いが 1/5〜1/20。ply56 で技巧2は詰み(mate−10)を読むのに生徒は −1595
  (「やや悪い」程度)。詰みを認識するのは ply58(mate−8)とほぼ詰む直前。
- **静かな局面 vs 取り合い**: 評価が「取り合いの途中で壊れる」現象(静止探索が効く典型)は今回の主症状ではない。
  生徒の静的評価は概ね滑らかで符号も合っており、問題は**全域的な度合いの鈍さ(0付近への圧縮)**。

### B-3. 診断のまとめ(どう粗いか)

1. **符号は信頼できる**(有利の向きはほぼ正しい。誤るのは ≤数百cp の near-equal のみ)。**符号反転バグではない**。
2. **大小(度合い)が0付近に圧縮**(飽和)している。「少し良い」と「完全に勝ち」を区別できない。飛車得 ≈ +0.6、
   飛車損 ≈ −0.13。これが核心の欠陥。
3. **帰結**: 探索の葉がどこも「ほぼ互角」に見えるため、深く読んでも勝ち/負けへ steer する勾配が立たない。
   実戦では「負けているのに気づかない」→ 受けに回らず depth1 の技巧2に押し切られる(Task 030 の全敗を説明)。

なぜ圧縮するか(仮説):
- **正則化**: `model_wd1e-3` は wd=1e-3 で重みを縮める = 出力 logit を小さく抑える方向。実測でも生徒 logit は決定的局面でも
  |logit|~1(=±600cp)程度までしか伸びない(Task 020 の logit 範囲 [−5.5, 5.8] に対し実戦では小さい)。
- **目標スケールの飽和**: 学習目標 `sigmoid(eval/600)` は勝勢局面で ≈1.0 に飽和 → 勾配が消える → モデルは決定的局面で
  大きな logit を出すよう押されない。結果として出力レンジが縮む。
- **データ分布**: 教師100万局面が near-equal 中盤に偏っていれば、大きな目標値をほとんど学ばない。

### 次段(評価強化)への設計判断
- **最優先: 再学習・キャリブレーション**(圧縮の解消)。
  - 正則化を緩める(まず既存 `model_wd1e-4` を `nnue-diag` で測り、圧縮が減るか確認 = 安い実験)。
  - 目標の見直し(cp 直接回帰 or 勝率変換の温度/スケール、決定的局面の重み付け)。
  - 容量/データ分布の見直し(決定的局面の比率)。
- **静止探索は本質的な解にならない**(全域的な度合いの鈍さは葉の安定化では直らない)。ただし near-equal の符号ノイズには
  二次的に効く可能性があり、評価強化の後に再評価。
- **キラー/ヒストリー等の速度系**は今回の主因でないので後回し(Task 030/031 で一貫)。
