# Task 082 — M6: ネット容量拡大(64ch×5L → 128ch×10L)— 容量が律速か

**目的**: 081 で M5 は健全飽和(gen200 vs WS2 +109 ≈ gen150 +133、延長で伸びゼロ=容量天井の兆候)。**一変数=ネット容量(64ch×5L→128ch×10L)**でループの上乗せ天井/絶対棋力が上がるか。深さ(d12 教師)は死(072 クラッシュ/飽和・067-071 自己ラベル=value 蒸留天井で policy/容量軸に直交)ゆえ不変、sims/warm-start 教師(d8)/lr も不変。**判定主軸=外部アンカー(vs champion)**(M5 で内部 elo が外部床に非転写のため)。実測 2026-07-08〜09、隔離環境(m4_* スクリプト流用、非コミット)、**リポジトリは文書のみ・Rust 無改変**。3-way 分解(warm-start の質 / loop 上乗せ / 外部到達)。

## ステップ0 — WS2-128 構築(容量効果その1=warm-start の質)
- m4_data(obs+v+action)流用、`m4_distill_train --num-channels 128 --num-layers 10`。**epoch 別 corr/top-1**: 0.868/0.341 → 0.891/0.372 → 0.899/0.398 → **0.905/0.400**(best ep4)。
- **旧 WS2(64ch)比 = corr 0.873→0.905(+0.032)、top-1 34.1%→40.0%(+5.9pp)**。→ **同じ d8 教師を大 net が明確によく吸収**(容量効果①=開始点の質↑を確認)。
- **詰まり(記録)**: 蒸留 batch=4096 は 64ch では動くが 128ch で **train_step OOM(7.37GiB)** → **batch 1024 に縮小**(VRAM 適応、一変数=net 容量には非干渉。loop の training_batch_size=1024 は M1 で 128ch 実績あり不変)。init eval が **NaN** に見えたのは**深 ResNet の BatchNorm 推論モード初期化アーティファクト**(未学習の moving stats と実活性の不一致が 10 層で発散)=学習が batch 統計で回れば epoch1 で解消(実際 0.868 で正常化)。無害。

## ステップ1 — WS2-128 からループ(078-081 と同一プロトコル、100 iter)
- 一変数以外不変(lr1e-4/sims32/batch256/steps512)。**VRAM 実測ピーク 13.4GiB(16 内、余裕 ~2.9GiB)**、**iter ~565s(median、64ch の ~1.4×=M1 の env 律速予測どおり)**、100 iter を **実 crash/restart 0 件**で完走(WARN_SLOW は 580s 閾値が 64ch 較正のため 128ch 常用域 577-663s で頻発する擬似警報=無害)。
- **監視推移**: 価値 corr **0.748(iter1 dip)→ 0.846 まで上昇 → 0.83 で安定**(64ch の 0.74-0.78 帯より高い=大 net は value をよく保持)/ 方策 top-1 0.411→0.377(緩やか適応、保持)/ episodes 平均 888。

## 3-way 分解(全て sims128 等条件)
### (A) warm-start の質(容量効果①)= 上記 WS2-128 corr/top-1 が 64ch 超(確定)
### (B) loop 上乗せ(容量が loop 天井を上げたか)
- **gen100(128) vs WS2-128(SPRT 0/+10, 上限 400)= accept_h1 @265 局、160-37-68, +126 elo(CI +86..+169)**。
- 64ch 基準: gen100(64) vs WS2-64 = +127、plateau +133(M4/M5)。→ **loop 上乗せは容量不変(+126 ≈ +130、CI 大幅重複)**。容量は warm-start の質(A)は上げたが **loop の自己対局増分は上げない**。
- カーブ(vs WS2-128): gen20 +168(n40) / gen50 +98(n40) / gen100 +126(n265)。n=40 の 2 点は CI ±100 超で散るが、大 N の gen100 が **+126 plateau** を確定(loop は早期に ~+120-130 到達し頭打ち=64ch と同型・同水準)。
### (C) 外部到達(絶対棋力=主判定)
- **gen100(128) vs champion**(byoyomi 100ms, 200 局): **0-6-194, score 0.015, elo −727(CI −998..−624)**。64ch gen200 = 0-2-198(−798)/gen150 = 0-4-196。→ **draw 6 vs 2-4、elo −727 vs −798=約 +70 elo の限界的改善**(warm-start の質↑が一部転写)。だが **0 勝・依然 ~−700 の床**(αβ depth~15 の壁は不動)。
- **gen100(128) vs gikou@6**(100 局): **0-6-94, score 0.030, elo −604(CI −868..−500)**。64ch = 0-0-100(完全床)→ **アーク初の gikou 床割れ**(WS1/WS2/gen-64 は全て 0-0-100 だった)。→ 外部アンカー**両方**が 128ch で改善。
- **WS2-128 vs WS2-64(100 局, クロスアーキ)= 71-17-12, +235 elo(CI +170..+320)**。→ **容量増は warm-start の実棋力を大きく上げる**(corr/top-1 の改善が +235 elo に転写)。
- **WS2-128 vs champion(100 局)= 2-3-95, score 0.035, elo −576(CI −996..−458)= アーク初の対 champion 勝利(2勝)**。**しかも loop 後の gen100(128)(0-6-194, 0勝)と統計的に同等**(CI 重複、両者床)→ **loop の +126 内部利得は外部に一切転写されず、対 champion の前進(勝ち・床割れ)は全て warm-start の質(容量)由来**。

### ★内部/外部スケールの非整合(M6 の核心的所見)
gen100(128) は内部(WS 系列比)で **~+235(warm-start)+ +126(loop)≈ +360 over gen-64** だが、**外部(vs champion)では −727 vs −798 = わずか +70**。**大きな内部利得が外部 αβ スケールで激しく圧縮される**(M5 の非転写を定量化)。=AZ 系ネットは αβ champion(depth~15 探索)とは別レジームにあり、内部改善の外部転写率が低い。

## M6 判定 = **部分 PASS(容量は warm-start の律速だが、loop の律速でも αβ の壁の律速でもない)**
- **PASS 側(外部改善)**: brief の「外部アンカー改善」clause を満たす。champion −798→−727(WS2-128 が**アーク初の対 champion 2 勝**)、gikou **0-0-100→0-6-94(アーク初の床割れ)**。容量↑ → warm-start の質↑(corr 0.905/top1 0.400、実棋力 +235 over WS2-64)→ 外部が限界的に前進。
- **FAIL 側(loop 天井は不変)**: gen100(128) vs WS2-128 = **+126 ≈ 64ch の +130**(CI 重複)。**loop の自己対局増分は容量不変**。容量は warm-start(開始点)を上げるが loop の上乗せは上げない。
- **★核心=内部/外部スケール非整合**: gen100(128) は内部で ~+360 over gen-64(+235 warm-start + +126 loop)だが外部はわずか +70。**loop の +126 は外部に非転写**(gen100 と WS2-128 は対 champion で統計的に同等)=**対 αβ の外部前進は全て warm-start(supervised・容量駆動)由来、self-play loop 由来はゼロ**。
- **★交絡=外部評価の探索予算**: 外部は AZ **sims128(~128 node/手)** vs champion **~1M node/手(100ms αβ)**。探索予算が桁違いに非対称=**外部床は「net 品質の壁」でなく「探索予算の壁」の疑いが濃厚**(M7 で切り分け必須)。

## M7 への申し送り(推奨順)
1. **★最優先・最安=外部評価の探索交絡を解く**: gen100(128) vs champion を **play-time sims を上げて**(512/800/…、AZ の思考時間は延びる)測り、外部床が下がるか。下がれば「壁は探索予算であって net 品質でない」= sims128 床は AZ の真の強さを過小評価。**これを測る前に net をこれ以上いじるのは早計**。
2. **loop 増分(+130 天井)を上げる=学習時 sims↑**: self-play の MCTS 訪問分布(方策教師)の質。M1 で sims は超線形高価だが、loop の +130 頭打ちの直接の律速候補(容量でなく探索が loop の律速の可能性)。
3. **warm-start をさらに上げる**: 容量が warm-start に効いた(+235)ので Transformer(容量効率, BACKLOG ch.2)/ 蒸留量 d8 2M→8M。ただし外部転写率が低い点に留意。
4. **規律**: 内部 elo は外部に転写されにくい=判定は**外部(champion/gikou、可能なら sims も振って)**で。内部 elo 追いは外部を保証しない(M5/M6 で二度確認)。
