# Task 150: なぜ雑巾絞りで伸びず、C が最も悪かったか

2026-10-21、Codex。指定資料・`DESIGN.md`・学習器を読み、保存重みとデータを CPU で測定した。

**結論: 自己ラベルへの適合は改善したが、水匠ラベルへの一致は全腕で失われた。H2 は部分支持、局面分布の違い H1 は実在する。ただし、どちらも C の順位を説明し切らない。C は全層で最も小さく動いており、標本にも大きな偏りはない。「Adam 初期の移動から回復する前に止まった」は未検証である。** 前回レビューの「8M なら穏やかな変更」という提案は、重みの距離については正しかったが、棋力の損失を小さくする保証にはならなかった。

保存済み対局の A −8.4 [−22.5,+5.7]、B −14.3 [−28.6,−0.2]、C −30.5 [−44.4,−16.7] を前提にする。A の小幅悪化は未確定、B は境界的、C の悪化は両物差しで確認されている。A/B/C の相互順位の有意差や学習 seed 間の再現性は、この区間からは決めない。

## 測定条件

- [解析スクリプト](../experiments/alphazero/t150_why_probe.py)、[数値と重みの SHA256](task150_why_metrics.json)。seed `20271501`、torch intra-op 4 / inter-op 1、CUDA 無効、QAT + Factorizer + tie、`forward * 600`。学習・探索・対局・commit・push はしていない。永続データは読み取りのみ。
- 自前 train 8,192 行、自前 val 全 50,000 行、水匠仕上げ集合 32,768 行、水匠 train 8,192 行を固定抽出。同じ行を全ネットで評価。C の学習行から別に 8,192 行を抽出。盤面統計は各集合最大 8,192 行。
- **水匠キャッシュの `train_*` を使用**。`val_*` は自前 val へのリンク。公開の「val7m」は task142 が 2 周学習済みなので、ここでの用途は知識の保持測定であり、未学習テストではない。水匠 train 標本は task142/150 の学習元ではないが、集合間の完全な非重複は未監査。
- 誤差の目標は ±2000 に制限、予測は制限しない。以下の評価値は **やねうら王の内部値**（表示 cp の約 0.9 倍）。CPU と元 GPU の丸め差は、自前 val MAE で最大約 0.008。

## H2: 水匠仕上げの効果を薄めたか — 部分支持、C の順位は説明しない

同一標本に対する **MAE / Pearson 相関**:

| ネット | 水匠仕上げ 32,768 | 水匠 train 8,192 | 自前 val 50,000（自己 d9） | 自前 train 8,192（自己 d9） |
|---|---:|---:|---:|---:|
| task129 | 418.0 / .8591 | 411.8 / .8729 | 407.2 / .8569 | 378.3 / .8764 |
| **task142** | **282.4 / .9118** | **304.2 / .9072** | 314.6 / .8690 | 240.6 / .9178 |
| A | 294.2 / .9076 | 311.2 / .9050 | **305.6 / .8710** | 221.7 / .9269 |
| B | 295.2 / .9069 | 310.4 / .9050 | **305.6 / .8708** | **217.5 / .9290** |
| C | 294.1 / .9080 | 312.3 / .9046 | 308.3 / .8702 | 228.3 / .9229 |

自己 d9 へは train だけでなく val でも改善し、水匠への一致は両集合で悪化した。これは目的間の競合を支持する。ただし水匠仕上げ集合の悪化は **B > A ≈ C**、別の水匠集合でも単調でない。**「水匠への忘却が C > B > A だから Elo もその順」は成立しなかった。** C の余分な約 20 Elo の損失を、この全体 MAE だけで説明する根拠はない。

水匠目標の `|y|<1000` に限ると MAE は task142 **256.1 → A 277.6 / B 279.8 / C 277.3**。極端値の clamp だけの問題ではない。平均残差を標本内で取り除いても、水匠仕上げ集合の MAE は **283.6 → 295.7 / 297.9 / 295.5** で、全体の定数ずれだけでもない（この補正は診断用、配備案ではない）。

task129 への単純な巻き戻りでもない。水匠集合で task129 からの出力 MAE は task142 **274.3** に対し A/B/C **305.0 / 306.6 / 310.2** と、むしろ遠ざかる。task129→142 の出力差への射影も 142=1 に対し **1.052 / 1.050 / 1.069**。水匠との一致を一部失いながら、別の方向へ動いたと読むべきである。

## H1: 局面分布は違うか、実戦で出力が動くか — 観測は支持、因果は未分離

盤面からの記述統計（すべて手番基準）。駒得は T146 と同じ便宜的な駒価値で測る説明変数で、学習や評価関数には入れない。

| 集合 | 平均絶対駒得 | 持駒総枚数 | 自玉の位置（筋 / 段） | 自玉2マス内の敵 / 味方 | 成駒枚数 | 王手中 | ラベル `|y|≥2000` |
|---|---:|---:|---:|---:|---:|---:|---:|
| 自前 train | 844 | 7.34 | 5.10 / 8.03 | .58 / 6.86 | 1.25 | 0% | 13.8% |
| 水匠仕上げ | 988 | 7.76 | 5.52 / 8.01 | .80 / 6.55 | 1.50 | 0% | 29.1% |
| 水匠 train | 1053 | 8.31 | 5.73 / 7.89 | .80 / 6.37 | 1.52 | 0% | 31.6% |
| task142 実戦 | 877 | 5.37 | 5.64 / 8.38 | .39 / 7.01 | .82 | 8.1% | — |

水匠集合は自前 train より駒の損得・成駒・玉周辺の敵が多い。実戦標本は持駒と成駒が少なく、自玉周辺の敵も少ない。ただしラベル分布の差には教師の違いも混ざり、局面だけの違いとは呼べない。

実戦は `floodgate/t142_20261019/me/records` の **10 棋譜、binbo_t142 が指す直前の 583 局面**。手数の中央値は実戦 59、水匠仕上げ 78、水匠 train 81。**自前 77 列と元 HCPE は手数を保持しないため、自前 train の実手数分布は復元できない**。復元 SFEN の末尾 `1` を手数統計に使っていない。

| task142 からの出力変化 | A | B | C |
|---|---:|---:|---:|
| 自前 val: 平均 / MAE | +42.1 / 81.9 | +39.4 / 88.9 | **+51.9** / 75.0 |
| 水匠仕上げ: 平均 / MAE | +50.4 / 86.5 | +50.3 / 94.9 | **+58.2** / 78.8 |
| 実戦: 平均 / MAE | +34.7 / 62.9 | +30.5 / 60.7 | **+47.6** / 63.6 |

**自前局面での学習は、実際に遭遇する局面の出力も動かした。C は総変化量が最大ではないが、手番側への平均的な楽観化が最大**。ただし正解ラベルのない棋譜で、この変化が悪いと断定できない。10 棋譜内の行は相関し、実戦の根局面と qsearch leaf の比較には処理段階・手数の交絡もある。探索中の葉の分布や、分布を揃えたときの Elo は未測定。

具体的には、自前 val の平均残差（予測−自己d9）は task142 **−59.3 → C −7.5** に近づく一方、水匠仕上げ集合では **−11.7 → +46.5** になる。自己教師に合わせる方向の移動が、水匠側では過大評価として現れる。ただし、上記の平均補正でも水匠 MAE は回復せず、この成分だけを原因にはしない。

## H3: C は少ない更新でなぜ悪化したか — 大移動・標本偏りは支持せず、途中経過は欠測

保存重みと task142 の層別 L2 距離（量子化前）。FT の末行は Factorizer を足し、tie を適用した実効表で、重複行を含む固定表現で比較した。

| 層 | A | B | C |
|---|---:|---:|---:|
| feature_transform.weight | 7.971 | 14.090 | **4.230** |
| ft_factor | 1.435 | 2.334 | **.689** |
| ft_bias | .0341 | .0401 | **.0229** |
| l0.weight / bias | .709 / .0252 | 1.023 / .0298 | **.313 / .0107** |
| l1.weight / bias | .552 / .0530 | .840 / .0674 | **.209 / .0261** |
| l2.weight / bias | .0748 / .00203 | .1072 / .00408 | **.0307 / .00104** |
| 実効 FT 表 | 19.157 | 31.752 | **9.453** |

**C は全層で最小**。終点だけから「最初に最も大きく飛んだ」とする証拠はない。もちろん終点の距離から、途中で飛んで戻ったかは分からない。QAT・非線形ネットなので、重み距離と Elo の単調関係もない。

C の mask は bool 63,950,000 行、選択数 8,000,000、**seed 20271500 で再生成した mask と全行一致**。4M 行ブロックの採用率は **12.490〜12.530%** で全域に分布。全ラベルの比較も以下の通りで、大きな標本偏りは見つからない。

| 対象 | 制限後平均 / 標準偏差 | `|y|≥2000` | `|y|≥30000`（詰みフラグとは別） |
|---|---:|---:|---:|
| 全64M | 45.778 / 1178.727 | 14.2602% | 4.2021% |
| C の8M | 44.991 / 1178.869 | 14.2655% | 4.1998% |

C の盤面標本も全域標本に近い（持駒 7.38 対 7.34、絶対駒得 857 対 844、自玉近傍の敵 .60 対 .58）。C の学習行標本でも自己 d9 MAE は **225.3**、A **220.3**、B **216.2**。C だけが自己教師へ極端に過適合した、という兆候もない。

実ログは全腕で epoch 0 と 1 しかない。val Huber は **109,170 → A 105,622 / B 105,765 / C 106,447**、学習中平均 loss は **65,214 / 64,090 / 67,247**。後者は各時点の異なる重みでの平均で、同じ終点での損失曲線ではない。更新は A/B **62,452** 回、C **7,813** 回。

学習器は重みだけ読み込み、Adam は全腕で新規作成する。新規 Adam の初動が不適切で、その後 A/B が局面ごとの調整を進めた可能性は残る。ただし最初の更新はバイアス補正により概ね `lr × sign(g)`（eps を無視）であり、moment が空というだけで巨大になるわけではない。**途中 checkpoint も `train_state.pt` も存在せず、B の約8k更新時の val・水匠一致は測定不能**。C は別の行順・mirror 乱数列なので、B の8k時点そのものでもない。現状は「C は局面固有の適合が少ない一方、共通の楽観化は既に起きた」という終点の記述まで。

## H4: 自己 depth-9 ラベルの質 — 限界を確定する材料は不足

自前 train で、自己 d9 と水匠仕上げ済み task142 静的値の MAE は **240.6**、val では **314.6**。探索値を静的ネットへ詰め直す信号は小さくない。ただし task142 自体は正解ではない。水匠局面には水匠ラベルがあるが、同じ局面の自己 d9 ラベルはなく、今回の forward だけでは教師同士の誤差・優劣は測れない。異なる局面集合の MAE 240.6 と 282.4 を比べて教師の質を順位づけることもしない。

前回の [T147 点検](task147_review_codex.md) では、実戦由来の同じ512静止局面で task142 の d9→d12 が両物差しとの相関を改善し、両深さの差の MAE は表示 cp で123.4、符号反転16.2%だった。浅い教師の揺れは候補に残るが、今回の C の原因を証明しない。**T145 の +70 も局面とラベルを両方替えた結果**であり、「ラベルだけの差」や「自前ループ全般の否定」には使えない。

## 次の実験（今回は実施していない）

追加の公開データは増やさず、自己パイプラインを本線に保つ。順序は期待 Elo の保証ではなく、機械時間当たりの切り分け能力による。

1. **最優先・安い診断: B の同じ行順を再走し、0 / 512 / 2048 / 7813 / 15626 / 62452 更新で保存。** 自己 val、水匠保持、現 binbo の静止化済み holdout と出力の平均移動を測る。元実測から GPU 学習約9.3分 + 保存・CPU診断。初動後に回復するかを1本で判定できる。保存点を大量に対局させず、仮説が支持された場合だけ warm-up 等の1条件を対照化する。
2. **既存データで最小の介入: task142 静的値を錨にした目標を1点。** 例 `0.5*clip(f142)+0.5*clip(d9)` を同じ固定8M・同じ更新数で学習し、Cと比較。新生成なし、元Cの学習は約70秒、別途8Mの静的値の生成費を小標本で実測する。CPUの小標本保持診断を先に行い、有望な1本だけ新seedの対局へ。全体定数の補正だけを本命にはしない。公開データは保持の物差しと従来量の軽い仕上げにとどめ、仕上げ前の効果を必ず分離する。
3. **本線の次: 現 binbo 自己対局→現 eval の qsearch leaf、勝敗・手数・対局IDを保存。** まず小集合を作り、ゲーム単位のholdoutと、同一局面で d9/d12 の教師品質を確認してから1〜数Mへ。小規模学習は採用重みから始める。前回512行の実測から1Mへ単純外挿すると探索worker時間は d9 約3.5h、d12 約17.9h（4並列の理想壁時計0.9h / 4.5h、自己対局生成は別）。分布・負荷・重い裾が違うためpilotで測り直す。分布と深さを同時に変えず、同一新局面の d9/d12 を対照化する。

全64Mの深い再ラベルやゼロからの再学習を先に反復する期待値は低い。判定対局は元実験でも学習より重く、別の作業の時間つき対局と競合するため、実行時の所要時間を別に見積もる。**今わかった失敗条件は「技巧2由来の既存局面へ、自分のd9をそのまま回帰する」こと。自己対局・勝敗・現探索分布を備えた雑巾絞りはまだ試していない。**
