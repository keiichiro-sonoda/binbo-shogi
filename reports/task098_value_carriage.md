# Task 098 — 共有幹で value は動いた。だが NNUE へは運ばれなかった(運搬路の壁)

**目的**: 097 で r=0.50 ループの外部正転写がレシピ水準で再現(+26)。だが勝者の value 塔は WS-T と byte 同一で、value 教師としては依然 WS-T。利得を製品 NNUE へ運ぶには value に利得を載せる改造が要る(方策橋は 092-0 で bridge null、value チャネルは 084 で +237/−145 の感度が実証済み)。実測 2026-08-02、`RUN_META dirty=0 exp_dirty=0`、実走 15:45〜23:33(**7.8h, rc=0**)。

## 一変数 = value 塔の扱い(完全二塔凍結 → 共有幹 + λ 正則化)
ブリーフの「二塔の value を凍結解除し `λ·MSE(v, v_WS-T)` を追加」は**証明可能な no-op** だった: `clone_as_dual` はネット全体を2つ独立に複製し、dual forward は互いに素なパラメータ集合へ2回 apply する。∴ policy CE の勾配は value に届かず、MSE は初期時点で `params["value"]==WS-T` ゆえ恒等的に0・勾配も0。**単一パラメータ集合に両ヘッド**とし、`loss = policy_CE + λ·MSE(v, v_WS-T)`(素の MSE。`optax.l2_loss` は½)。他は 096 の r=0.50 アームと完全同一(sims32/65,536 states/iter/lr1e-4/batch128/25 iter/`seed=anchor_seed=20260714`)。副次効果として自己対局が短縮(実測 540s→~372s、`states_s` 120→177)=二塔が MCTS 各ノードでネットを2回評価していたため。

## λ 選定(外部 Elo を一切見ずに value 健全性のみで、事前登録規則を適用)

| λ | `value_mae_wst` | `value_std_ratio` | `value_corr_teacher` | `value_mse` | 30cp基準 |
|---:|---:|---:|---:|---:|---|
| **3** | **44.3** | 0.9985 | 0.9370 | 9.1e-4 | **✓** |
| 30 | 28.0 | 1.0006 | 0.9362 | 3.7e-4 | ✗ |
| 300 | 19.8 | 0.9960 | 0.9360 | 1.3e-4 | ✗ |

**ラダーは綺麗に効いた** — 拘束を強めるほどドリフトが単調に減り、健全性は全点で維持。事前登録どおり「**mae≥30cp・std_ratio≥0.95・corr≥0.92 を満たす最大の λ**」= **λ=3(`qualified`)**。
なおラダー範囲と規則の向きは、事前登録に先行した1 iter の配線スモーク(機構のみ観測、結果は未観測)で決めた: λ=3 の罰則寄与は policy CE の **0.08%** で実質無拘束だったので {0.3,3,30} でなく {3,30,300} とし、1 iter で 35.3cp 動く以上律速は「動くか」でなく「崩壊するか」なので「最小の λ」でなく「動かせる範囲で最大の λ」とした。**結果的にこの調整は正しかった**: λ=30 で既に 30cp を割るので、旧ラダーなら λ=0.3 が選ばれ拘束はさらに弱かった。

### なぜ運ばれなかったか — ラベル統計が答えを持っている
`az_rescore` が出す 2M 教師ラベルの素性を、084 と同じ軸で並べる:

| 教師 | cp std | 技巧2との corr | \|Δcp\| median |
|---|---:|---:|---:|
| 技巧2@d8 探索cp(clip) | 1778 | — | — |
| **098 候補(共有幹 25iter)** | **1502** | **0.958** | **201** |
| **WS-T(対照)** | **1500** | **0.957** | **202** |
| (参考)WS2-128 [084] | 1471 | 0.942 | 248 |
| (参考)gen100 [084] | 698 | 0.896 | 365 |

**候補と対照はラベル素性が実質同一**(std 1502 vs 1500、corr 0.958 vs 0.957、median 201 vs 202)。∴ **m4_data val 上で 59.2cp 動いたことは、2M 教師集合の上では「技巧2 を同じ精度で近似する別の点」への移動でしかなかった**。両者とも技巧2 と corr 0.958 で一致し、互いに 59cp ずれている — つまりドリフトは**同じ関数まわりのノイズであって新情報ではない**。学生が区別できないのは当然の帰結である。

これは 085/nodchip の命題(**教師上書きが効くのは上書き元が真に強い=新情報を持つ時**)の、value チャネルでの直接的な再確認になっている。

## 判定の含意 — 壁は「value が動かないこと」ではなく「運搬」そのもの
本タスクは NULL 3分岐のうち **`NULL_LAMBDA_TOO_LARGE` を明確に排除**した(59.2cp ≫ 30cp)。∴ 残った説明は運搬路の壁ただ一つ:

> **ループはプレイヤーを強くし(tripwire +68.7)、value も動かした(59.2cp、圧縮なし)。それでもその value を教師にした NNUE 学生は、WS-T value の学生と区別できない(−0.87 [−23.9, +22.2])。**

091(教師0)→093(外部悪化)→094(悪化停止)→095(supervised枯渇)→096(混合が+28.65)→097(レシピ水準で再現)→**098(利得は NNUE へ運ばれない)**。単機ループの外部利得は実在するが、**製品への運搬路は少なくともこの経路では開いていない**。

## 申し送り
### (a) 運搬をなお追うなら — 「新情報」を作る方向
ラベル統計が示したのは「候補も WS-T も技巧2 の同じ近似」。∴ 運搬の前提は **value が技巧2 と違う方向へ、かつ良い方向へ動くこと**。現行ループの value は policy 学習の副作用でしか動かず、技巧2 近似の manifold から出ない。候補:
- **value に独立の教師信号**(自己対局リターン)を与え λ で錨を打つ = 選択肢B(082 の再演に鎖を付ける)。082 は無拘束で std 0.475 まで潰れたが、本タスクで λ の効き目(30 で 28cp、300 で 19.8cp)が実測できたので、崩壊させずに動かす λ 帯は見えている。
- **深い技巧2**(d12+)や独立に強い DL エンジンの value = nodchip [R1] の +R100 が効いた条件そのもの。GPL 内で入手可能かは別途。
- ただし **085 の 2M→32M 反転**があるので、2M で勝っても 32M 確認(rescore 37分+学習3h02m+対局2.5h ≈ 6.2h)までは資格に過ぎない。

### (b) 閉じるなら — 何が確定したかの総括
- 単機ループの**外部正転写は実在し再現する**(096/097、+26〜+27)。**共有幹にすると player はさらに強い可能性**(tripwire +68.7、要確認)。
- しかし**その利得は value チャネル経由で NNUE へ運べない**(本タスク)。方策チャネルも 092-0 で bridge null。∴ **既知の運搬路は両方とも閉じている**。
- 資源復帰先は BACKLOG の既知正方向(32M→64M 蒸留 ~5.6h生成/SPRT vs `task064_32m_lr1e-5`、小/中データの AZ 平滑化ハイブリッド)。
