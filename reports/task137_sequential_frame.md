# Task 137: 標準 frame を途中で止める案（既存対局の再生のみ）

## 結論

推奨は **不採用（現行の標準 frame の全面置換として）**。Pocock 型のペア bootstrap なら、実データ再標本化で差ゼロの誤判定は **better 2.118% / worse 1.996%**（固定方式 2.568% / 2.496%）。±40 Elo は平均 **989〜992 局（約 38% 削減）**、±80 Elo は **383 局（約 76% 削減）**で、大差を早く判定する目的には合う。

ただし最大 1,600 局のまま繰り返し見る補正を入れるため、±20 Elo の検出力は **固定 37.5〜37.7% → 逐次 25.2〜25.4%**、±40 Elo でも **90.9% → 80.9〜81.2%**に下がる。今の実験で拾いたい +20〜30 Elo の改善に対し損が大きい。実例でも 2 件の固定 better が no_difference になった。これらが本当の改善かはリプレイでは分からないが、検出力の低下自体はシミュレーションでも明確。大差を優先してこの損失を許す実験なら、今回の規則を事前登録して使う選択肢はある。

エンジン・GPU・学習は使っていない。`std_frame.py` と `docs/evaluation_protocol.md` は変更していない。追加ファイルだけの指示に従い、`STATUS.md` も変更していない。コミット・push はしていない。

## 方法

**Pocock 型の一定境界、最大 8 回。** chunk 0〜7 を順番に進め、各回とも tanuki- @20,000 と AobaNNUE @10,000 の **両方の 100 局**が揃ってから 1 回だけ判定する。候補・対照は 100,000 nodes、標準 seed は 20272001〜08。途中の片方だけを見て止めない。序盤の先後 2 局を分けない。

共有序盤の先後 2 局の候補得点平均を A、対照を B とし、D = A − B とする。各時点で両 anchor を等数まとめる。表示する点推定は従来どおり `Elo(mean A) − Elo(mean B)`。Elo 変換は単調なので、その符号は `mean D` の符号と同じ。各 bootstrap 標本でも同じことが成り立つ。従って、**0 を除くかの判定に限れば、Elo 差の percentile bootstrap を D の percentile bootstrap に置き換えられる**。Elo の区間の端点そのものは置き換えられない。

D は −1, −0.75, …, +1 の 9 値。経験分布の確率多項式を n 乗して、n 組を復元抽出したときの和の分布を FFT で計算する。候補と対照を独立には引き直さない。これは **bootstrap 分布の正確な計算**であり、有限標本で被覆率が正確という意味ではない。

各回の両端を `alpha = Phi(−2.6) = 0.0046611880` にする（各時点では約 99.07% の区間）。下限 > 0 なら better、上限 < 0 なら worse、それ以外は続行。8 回目までどちらにも触れなければ no_difference。最後に通常の 95% CI へ戻すことはしない。no_difference は「区別できない」であって同等性の証明ではない。

正規近似での Pocock 設計では `corr(Z_j, Z_k) = sqrt(j/k)`。この結合分布で、8 回のどこかで +2.6 を越える確率を数値積分すると **1.989678% / 側**になる。反対側での停止を無視した値なので、両側停止の各側の確率の上限になる。2.5% を使い切らず、bootstrap の近似誤差の余地を残した。これは Bonferroni ではなく、相関した 8 回を見る group-sequential 設計である。根拠は [gsDesign の canonical joint normal の説明](https://keaven.github.io/gsd-tech-manual/testing.html) と [Pocock の一定境界の定義](https://keaven.github.io/gsd-tech-manual/gsdesign.html)。

bootstrap の分位点を使う規則と正規の境界は漸近的に対応する。従来の固定 bootstrap と同様、任意の有限標本分布に対する誤判定率の厳密保証はない。下の実データ再標本化で、近似がこの物差しで許容できるかを確認した。候補案を探す小規模試行では O'Brien–Fleming 型も見たが、±40 Elo で停止が遅かったため一定境界を選んだ。以下の本計算の前に規則を固定した。これは過去ログを使った設計作業であり、前向きの事前登録済み実験とは呼ばない。

## Monte-Carlo

標準の 8 比較 × 400 序盤 = **3,200 block 記録**を材料にした。1 block は同じ序盤における「候補・対照 × 先後 × anchor 2 本」の実際の結果。両 anchor を一緒に引き直すので、同一序盤の anchor 間の相関も残る。3,200 個の独立した新しい序盤があるという意味ではない。標準 seed の序盤は比較間で共有している。確認実験は材料に入れない。

候補と対照を block ごと丸ごと交換した記録を等量加え、0 差の分布を作った。次に `exp(lambda * block平均D)` で抽出確率を傾け、母集団の **pooled Elo 差**が 0、±20、±40、±80 になる lambda を解いた。得点を足して範囲外の値を作る操作はしない。引き分け・ペア内の相関・anchor 間の相関を持つ実際の結果の組だけを使う。

各差 **50,000 回**、乱数 seed **20273701**。1 回ごとに 8 chunk の同じ標本を固定方式と逐次方式に渡す。固定方式も得点差の経験分布を 800 回畳み込んで両端 2.5% を取り、元の percentile bootstrap の無限反復極限を計算する。元の 200,000 回抽出の乱数誤差は加えない。全 9 実例で元実装との符号一致を確認済み。

プラスの真の差では better 欄、マイナスでは worse 欄が検出力。0 の行では各側の誤判定率。単位は %、局数は候補だけ。

| 真の差 (Elo) | 固定 better | 固定 worse | 逐次 better | 逐次 worse | 固定平均局数 | 逐次平均局数 | 局数削減 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| +0 | 2.568 | 2.496 | 2.118 | 1.996 | 1,600 | 1,563.0 | 2.3% |
| +20 | 37.506 | 0.012 | 25.174 | 0.128 | 1,600 | 1,433.8 | 10.4% |
| -20 | 0.014 | 37.724 | 0.118 | 25.356 | 1,600 | 1,433.1 | 10.4% |
| +40 | 90.876 | 0.000 | 80.864 | 0.008 | 1,600 | 992.1 | 38.0% |
| -40 | 0.000 | 90.912 | 0.010 | 81.224 | 1,600 | 989.2 | 38.2% |

差ゼロの 95% Wilson 区間（%）は次のとおり。

固定: better 2.568% [2.433, 2.710] / worse 2.496% [2.363, 2.636]。

逐次: better 2.118% [1.995, 2.248] / worse 1.996% [1.877, 2.122]。

逐次方式の両側とも上限が 2.5% 未満で、同じ標本での固定方式も下回った。±40 Elo の平均局数の Monte-Carlo 標準誤差は約 2.13 局、±80 Elo は約 0.86 局。235 種の実測 block の組合せを使っている。全ての確率・区間・停止回の分布と材料の SHA256 は `task137_simulation.json`。

これらの区間は Monte-Carlo の抽出誤差だけを表す。実データの pool を別の将来の候補にも当てはめられるかの不確かさは含まない。対照の記録を使い回して候補を選ぶ偏りや、複数タスク全体の誤判定を解消する方法でもない。

## 採用する場合に正本へ必要な変更（このタスクでは未変更）

1. 第 1・3 項の「各 800 局以上」を「各 100 局での事前指定 8 回、最大各 800 局」へ変更する。anchor、nodes、seed、共有序盤での対照の再利用は維持する。
2. 判定はこの一定境界とペア単位を明記する。最終回に通常の 95% CI を使い直さない。片側だけの途中集計、chunk の並べ替え、結果を見て look を追加することを禁止する。
3. better は新しい seed での確認の資格だけとする。確認は従来の固定 1,600 局・95% CI を維持し、標準 frame と合算しない。確認 seed はタスクごとに事前登録する。
4. 停止時の Elo 差は記述値とし、逐次の区間が **得点差単位**であることを明記する。no_difference の意味と検出力の損失も載せる。
5. 将来の driver は chunk ごとの両 anchor が終わるまで判定せず、確定したら次の chunk を投入しない。既存 `std_frame.measure` は先に全 chunk を走らせるため、そのままでは局数を節約できない。先行実行中の余分な対局も実使用局数に数える。

ここでの削減は候補の対局数であり、実時間の測定ではない。4 並列で先の chunk まで投入する運用を変える必要があるため、28.1% の局数削減を、そのまま 28.1% の待ち時間短縮とは読まない。

## 実行・API・検証

作業ツリーのルートで実行する。

```bash
source scripts/env.sh
export PYTHONPATH="$PWD"
export PYTHONDONTWRITEBYTECODE=1 OPENBLAS_NUM_THREADS=1
"$VENV_PY" experiments/alphazero/seq_frame.py replay --output reports/task137_replay.json
"$VENV_PY" experiments/alphazero/seq_frame.py simulate --trials 50000 --output reports/task137_simulation.json
"$VENV_PY" -m unittest experiments.alphazero.test_seq_frame -v
```

`--logs`（既定は `$LOGS_DIR`）で入力を指定できる。`--output` は作業ツリー内だけに書ける。結果 JSON に材料のファイル名と SHA256 を残した。再実行時に新しい完全 frame が増えていたら棚卸しも変わる。未知の候補の対照を勝手に推測せず、出典つき対応表の追加を要求する。古い node 数・不完全 frame・基準としてだけ存在する eval を明示して除外する。

将来の driver は `sequential_looks(candidate, base)` を呼ぶ。入力は `{tanuki: rows, aoba: rows}`、行は既存 parser と同じ `score, color, opening_seed, opening` を持ち、chunk 順に並べる。両 anchor の長さが同じ 100〜800 局の prefix も受け付ける。出力は `look, candidate_games, delta_elo, score_delta, bounds, bounds_scale, tail_alpha, decision`。prefix の途中なら `continue`、初めて terminal 判定が出た時点で generator が終了する。driver は terminal 判定を保存して以後呼び直さない。

8 個の unittest が通った。FFT は小標本の bootstrap 全列挙を独立の正解として照合し、正規境界の積分は独立した 200,000 本の Gaussian random walk と照合した。他に、得点の単局でなく先後ペアが単位であること、候補・対照の交換対称性、prefix、終端判定、不整合・旧物差し・欠けた chunk の拒否、傾けた母集団の真の Elo を確認した。Rust・合法手生成は変更していない。
